# Deployment config — multi-tenant SaaS in the cloud. The shape a third-party
# builds their own brandnana-style product on. Fill the <...>, then
# `work deploy validate <file>`  →  `work deploy apply <file>`.
# SECRETS are NOT in this file — set them in your deploy ENV:
#   WB_S3_KEY / WB_S3_SECRET   (object storage)
#   WB_DATABASE_URL            (the Postgres DSN)

* cloud-saas                                                 :deployment:
  :PROPERTIES:
  :ID:               cloud-saas
  :ENGINE_PLACE:     cloud
  :PROVIDER:         fly
  :APP:              <your-app-name>
  :TENANCY_MODE:     multi
  :STORAGE:          s3
  :STORAGE_ENDPOINT: https://s3.us-east-1.amazonaws.com
  :STORAGE_BUCKET:   <your-bucket>
  :STORAGE_REGION:   us-east-1
  :DATABASE:         postgres
  :AUTH:             clerk
  :PROFILE:          <path/to/your/profile>
  :REGION:           iad
  :END:

** Notes
   STORAGE: s3 is any S3-compatible store — flip STORAGE_ENDPOINT to R2 / B2 /
   Tigris / MinIO and nothing else changes (one Elixir S3 client, many backends).
   DATABASE: postgres is required for multi-tenant — sqlite would serialize every
   tenant through one writer (validate rejects that combo). PROVIDER is the cloud
   extension point (default fly); the engine contract is identical across hosts.
