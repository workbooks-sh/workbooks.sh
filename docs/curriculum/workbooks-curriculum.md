# Workbooks — Learning Center Curriculum

> The complete conceptual learning path. Deep, jargon-light lessons for people with no technical foundation (managers, marketers, vibe-coders, anyone building with Claude). Each lesson teaches one big idea thoroughly and links out to the deep documentation pages for the literals. The order is the learning path.

**8 units · 20 lessons**

---

## Contents

1. **Foundations** — What the whole thing is made of — before any of the moving parts.
2. **Making things** — How a workbook gets real abilities, and how you drive it.
3. **The engine** — Where a workbook stops being a file and starts being a living service.
4. **Agents** — Software that does work on its own — what that really means, and how to keep it honest.
5. **Automation** — Plans that aren't just notes about the work — they ARE the work.
6. **The disk** — Where the work lives — a place to keep things that travels with the project.
7. **Trust & sharing** — How something you can copy infinitely stays trustworthy and safe to share.
8. **Under the hood** — Optional. The why behind the magic, for the curious.

## Unit 4: Agents

*Software that does work on its own — what that really means, and how to keep it honest.*

### 4.1  What an agent really is
`what-an-agent-is` · 📝 Planned

**Teaches:** Strip away the hype: an agent is a loop — it reads, it acts, it looks at what happened, it goes again. Understand that one loop and the rest stops being magic.

**Reference docs:** `agents`, `loops`, `authoring`

### 4.2  Agents that keep working when you're not watching
`agents-that-persist` · 📝 Planned

**Teaches:** How an agent goes from a thing you chat with to a thing that runs on its own — standing watch, taking shifts, resting between runs, and pausing to ask you when it should.

**Reference docs:** `spawning`, `orchestration`, `fleets`, `dreaming`, `human-in-the-loop`, `runtime-config`, `rehearsals`, `context-repo`

### 4.3  Knowing whether the agent actually did well
`did-it-do-well` · 📝 Planned

**Teaches:** The hard part of trusting software that thinks: how you measure whether it did a good job, catch it when it drifts, and keep a record you can't fake.

**Reference docs:** `evals`, `the-ledger`

`secrets-in-the-open` · 📝 Planned

**Teaches:** The surprising trick: part of a file you give to everyone can be readable only by the one person holding the right key — locked in the open, opened only on permission.
