** Font weight analysis

Baloo 2 Variable ships 4 language subsets (latin, latin-ext, devanagari, vietnamese).
On-device only latin (143 KB woff2) is fetched. Devanagari (115 KB) is bundled unnecessarily.
Nunito ships 5 subsets; only latin (39 KB) matters.

| Font family    | Subsets bundled | Needed | Waste |
|----------------+-----------------+--------+-------|
| Baloo 2        |               4 |      1 | 3 (290 KB) |
| Nunito         |               5 |      1 | 4 (129 KB) |
| Fraunces       |               2 |      1 | 1 ( 68 KB) |
| Archivo        |               3 |      1 | 2 (102 KB) |
| Phosphor icons |               2 |      2 |    0       |

Total recoverable font waste: ~589 KB WOFF2. Action: switch to subset-only imports in shared.js.
Not a blocker — WKWebView loads subsets on demand based on unicode ranges in the CSS; unused
subsets are not fetched even if bundled. Impact is app bundle size on TestFlight, not runtime.

* Delivery model: Capacitor app vs single-file workbook

The issue asks about "inlining into one .html WKWebView parses at boot." This applies to the
*workbook export* format (=.html= with all assets base64-inlined). The Capacitor app uses a
different path: assets are copied to the app bundle and served from =capacitor://localhost= as
real files — NO base64 inflation.

| Delivery                | Boot parse target | Base64 inflation |
|-------------------------+-------------------+------------------|
| Capacitor app (current) | Not applicable    | None             |
| Single-file workbook    | ≤ 2 MB parse      | ×1.37            |

*Ruling:* Do NOT declare single-file workbook format for AdBuy v1. The Capacitor delivery
model has no inlining constraint. Revisit if/when a workbook export is wanted for distribution.

* WKWebView JS heap limits (floor device: iPhone SE 2020, iOS 16)

| Device          | Reported JS heap limit | Notes                         |
|-----------------+------------------------+-------------------------------|
| iPhone SE 2020  | ~60 MB                 | Floor device (2 GB RAM)       |
| iPhone 12 mini  | ~150 MB                | Mid-tier (4 GB RAM)           |
| iPhone 15       | ~300 MB+               | Current flagship              |

AdBuy at v0.1 peak runtime heap (estimated):
- WASM module: 262 KB compiled → ~1–2 MB linear memory
- JS engine (Vite bundle): ~120 KB code + runtime structures ≈ 5–10 MB
- DOM (4 screens, cards): low, <5 MB
- Font render buffers: handled by OS glyph cache, not JS heap

Estimated peak heap: ~15–25 MB. Well within iPhone SE floor (60 MB).
At 160-card scale with DOM card nodes live: add ~5 MB → still well within floor.
