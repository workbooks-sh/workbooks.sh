Deep-Research Concurrency

A living workbook that is its own experiment: it fans out N concurrent deep-research agents inside the real nexus BEAM runtime, each doing live web search over your OpenRouter subscription, and reports where the ceiling actually is.

The question: how many long, multi-round deep-research agents can one nexus run at once? The answer below was measured, not guessed — on qwen/qwen3.7-plus:online (OpenRouter's web-search plugin), billed to the live subscription.

Every agent runs a 3-round loop: R1 live web search on its subtopic → R2 a deeper grounded follow-up (also live search) → R3 a synthesis pass (no search, cheaper). Two of three rounds hit the open web with real, dated citations.

The orchestrator (the actual source that ran)

One BEAM Task per agent, Task.await_many/2 as the barrier. The runtime's Nexus.Llm.complete/2 is the only seam — it defaults to OpenRouter and reads OPENROUTER_API_KEY. Concurrency is free on the BEAM; the interesting limit is elsewhere.

Full source: nexus/scripts/deep_research_stress.exs. Run it yourself: cd nexus && WAVES=4,8,16 mix run scripts/deep_research_stress.exs.

16 agents ran in 430 s — a 9.1× speedup over running them one at a time (~245 s each). Cost per agent stayed flat ($0.0277 → $0.0274): no per-concurrency penalty, no rate-limit throttling from OpenRouter at this width. The parallelism is real.
The ceiling is latency, not concurrency. The BEAM spawns N agents trivially and OpenRouter served 16 wide without throttling — the real limiter is per-request wall time. A thinking model plus the web plugin takes ~100–160 s per search round, which brushed the runtime's old hard-coded 120 s HTTP timeout (the only failures: 1/4 then 2/16, all :timeout, none from rate limits). Lift that ceiling and the practical width goes much higher.

The memory ceiling — and how we moved it

The agent is a cheap BEAM process; the LLM call is remote. The real RAM cost is the wasmtime subprocess each render spawns (Blitz: Stylo + Taffy + DOM). So the OOM wall is set by peak simultaneous renders, not agent count. We ramped render-active load on distinct pages until peak RSS (beam + all wasmtime) crossed a 1GB budget.

Diagnosis: every wasmtime run render_text.wasm cold-JIT-compiled the 9.6MB module on every call — ~0.7s and ~120MB of Cranelift working set, dwarfing the actual render. Nearly 100% of the cost was recompilation.

AOT moved the hard ceiling from ~7 to ~15 simultaneous renders on 1GB (marginal 103→60 MB/render). And past the slot limit the gate caps concurrent renders — at requested 12 and 16, wasm processes held at 10, RSS plateaued, zero failures, throughput still climbing. The OOM became a queue.

Two fixes shipped

  • AOT .cwasm cache (Nexus.Wasm.Aot) — compile each module once, run --allow-precompiled. Per render: 0.24s→0.14s, 121MB→47MB, byte-identical. The cwasm is read-only file-backed code, so the OS shares its pages across every concurrent render — and across tenants, with zero isolation impact (each render keeps its own private linear memory).
  • Bounded render lane (Nexus.Wasm.Gate) — a monitored semaphore sizes render slots to host RAM (~1 per 100MB → ~7 on a 1GB box). A burst queues instead of fork-bombing wasmtime into an OOM. Agent count now decouples from the memory wall: thousands of agents share a handful of render slots, because each agent renders for ~0.6s then waits ~82s on the LLM.

The north star: deep-research agents per 1GB

The whole point — how many concurrent deep-research agents fit on a 1GB Fly machine? We moved it ~27× across four changes, each measured:

At 100 agents reading back-to-back (1980 pages in 12s) the runtime sat at 718 MB — no OOM in sight. Renders stay a fixed gated slice; the LLM is remote (~0 local RAM). With realistic LLM think-time between reads, far more agents fit. The ceiling is no longer wasm, no longer the DOM — it's just BEAM process state, which is cheap.

Verdict

  • ✅ Your OpenRouter subscription drives the nexus runtime directly — default provider, live billing.
  • ✅ Deep web research works with no keyed search provider — OpenRouter's :online plugin returns real, dated URLs + citations.
  • ✅ Many agents research concurrently in one real BEAM runtime; orchestration is plain Task.async.
  • ⚠️ The scaling wall is request latency (slow thinking + web plugin), now relieved by a configurable timeout. A faster/non-reasoning model lifts the practical ceiling far higher.
