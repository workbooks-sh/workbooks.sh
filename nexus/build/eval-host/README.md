# eval-host — the shared StarlingMonkey JS engine (cap-enabled)

`priv/eval-host.wasm` is the one StarlingMonkey engine `Nexus.JsEngine` runs. Toolkit JS is fed to its
`run(input)` export as **data** (no per-toolkit wasm build). This dir is the **build recipe** (the
artifact itself is gitignored, ~11MB, built on a provisioned/build machine — like `coreutils.wasm` /
`clang.wasm`).

## What the cap-enabled engine adds

The engine imports a `toolkit-caps` interface and exposes each cap to the eval'd JS as a global
`__cap_<name>`. A toolkit's transpiled `$host = { store: __cap_store, … }` (from
`Nexus.Toolkit.Caps.host_js/1`) then calls real, host-resolved, **path-scoped** capabilities.

Validated end-to-end in the design spike (`/tmp/cloud-design-scratch/spike/caps-evalhost`): a cap-using
toolkit ran through this exact shape with path-scoped isolation (path A's store invisible to path B).

## WIT world (`evalhost.wit`)

The cap interface is generated by `Nexus.Toolkit.Caps.wit/1` for the full cap set; the world imports it
and exports `run`. See `evalhost.wit` here (the full-cap version).

## Bootstrap (`evalhost.js`)

Binds the WIT cap imports to `__cap_*` globals, then `run(input)` evals the toolkit driver and returns
its last expression (a JSON string). See `evalhost.js`.

## Build (on a machine with the bytecodealliance toolchain)

```bash
# jco bundles ComponentizeJS + StarlingMonkey + wizer (native node — BUILD machine only, never a nexus)
npx @bytecodealliance/jco componentize evalhost.js \
  --wit evalhost.wit --world-name evalhost \
  -o ../../priv/eval-host.wasm
# optional: wasmtime compile -> cwasm for cached fast instantiation
```

The native node toolchain runs ONLY here, once, to produce the wasm artifact. At runtime every nexus
loads pure wasm under wasmtime — no native code, no per-toolkit build (see
`/tmp/cloud-design-scratch/spike/NODE-ISOLATION.work`).

## Runtime wiring (already in place)

* `Nexus.JsEngine.eval/2` accepts `opts[:imports]` (Wasmex.Components shape) — passed straight to the
  component, resolving its `toolkit-caps` import.
* `Nexus.Toolkit.Caps.imports/2` builds that map from `bind/2` (path-scoped, grant-filtered).
* `Nexus.Toolkit.Js.invoke/4` threads `opts[:path]` + `opts[:grants]` → imports + the `$host` binding.

So once this engine is rebuilt with the cap import, the runtime path is closed: `invoke(name, fun,
args, path: {op,app,comp}, grants: [...])` runs the toolkit with real path-scoped caps.
