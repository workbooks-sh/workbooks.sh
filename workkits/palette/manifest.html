ONE toolkit holding the whole set of WASM build/runtime tooling — NOT separate packages. Each entry in =runtimes/= is a pinned prebuilt (or build recipe) for a language: fetch + sha-verify + (unpack) + register as a sandboxed command. Run untrusted source THROUGH them with no OS process and no host access beyond a granted preopen. Build them: - =work kit build palette= → build/register every runtime in the set - =work kit build palette <name>= → just one (e.g. =python=) Runtimes (each = runtimes/<name>.org, a pinned spec): | Runtime | Command | Kind | Source | |----------+----------+-----------------------+--------------------------------| | =qjs= | =qjs= | JS engine (single) | quickjs-ng qjs-wasi.wasm | | =python= | =python= | CPython 3.12 + stdlib | VMware WLR (wasi-sdk) tarball | | =ruby= | =ruby= | CRuby 3.3 + stdlib | ruby.wasm wasip1-full tarball | | =go= | =go= | Go interpreter | yaegi → gobuild wasip1 (go run <f>) | | =lua= | =lua= | Lua 5.4 (single) | wasi-sdk build (sjlj; -W exceptions=y) | | =zig= | =zigdemo=| Zig → wasm (authoring)| native zig (zigbuild; compile-to-wasm, no interp) | The =.wasm= artifacts are NOT committed (derived; DeployKit fetches them from the pinned specs). Only the pinned manifest set lives in git.
