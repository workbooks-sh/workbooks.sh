A *knowledge + assets* toolkit: a tiny, type-dispatched avatar engine — "many art styles, one DiceBear-like API." Parts that ship together — - =dist/open-avatars.js= — the renderer. One self-contained file, *zero dependencies*. Pure string→string (=avatar(pack, seed, opts)=), so it runs in a browser =<script>= (as =window.OpenAvatars=), as an ES module, in Node at build time, and in the runtime's QuickJS wasm JS lane. No DOM, no Node APIs, no =fetch=. =avatar()= routes by a pack's =type= (assembled / gallery / procedural). Bad input degrades to a 1×1 canvas, never throws. - =packs/<pack>/= — an *avatar pack*. Each declares a =type=: - *assembled* — a directory of SVG atoms grouped by category + a =pack.json= that calibrates each category on a shared canvas (open-peeps). - *gallery* — a list of whole avatars; =kind:svg= inlines them, =kind:raster= records an id list + path template and returns an =<img>= (transhumans, pixabots). - *procedural* — ships a pure =generate(seed,opts)→svg= the core calls (boring, jdenticon, minidenticons, pixitar). - =scripts/bundle-pack.mjs= — the build step. Type-aware: strips assembled atoms / gallery-svg figures to inner drawables, or writes the tiny raster id list, or copies a procedural =pack.json=. - =LICENSES.md= — honest per-pack attribution (all MIT or free-for-commercial). - =skills/= — how to use it: plug-in recipes, the pack types + how to add each, and the seed/crop/monochrome authoring semantics. *Determinism is the whole point.* A seed string is hashed (FNV-1a) — over a sorted category list (assembled) or a sorted id list (gallery), or by the pack's own generator (procedural). The same seed always yields byte-identical output — the DiceBear contract. No randomness, no timestamps, no per-render state. (Ports keep their source library's exact hash for byte-parity: jdenticon =d=-strings and minidenticons rects match the upstream npm packages.) *Monochrome is a stance, not a law.* Assembled open-peeps atoms ship black-on-white and the renderer never recolors them. *Gallery* and *procedural* packs keep their native color by default (transhumans/pixabots/boring are colorful); procedural identicons that allow it expose an =opts.monochrome= B&W switch. To theme an assembled avatar, set =opts.background= or style the host =<svg>= from CSS. See =skills/authoring=. The shipped styles: *open-peeps* (assembled, Pablo Stanley/CC0, 132 atoms), *transhumans* (gallery/svg, 38 colorful figures, Pablo Stanley free-commercial), *pixabots* (gallery/raster, 2000 robot bitmaps, served by id from a base path), *boring* (procedural marble+beam, MIT), *jdenticon* (procedural, MIT), *minidenticons* (procedural 5×5 mirrored, MIT), *pixitar* (procedural pixel grid, MIT). Full attribution in =LICENSES.md=. Three crops frame an *assembled* figure (gallery/procedural packs ship one fixed framing each): | Crop | Frames | Draws | |----------+---------------------------------+-----------------------------| | =circle= | head + face, disc-clipped | everything *except* body | | =bust= | head + shoulders | all categories | | =full= | the whole figure on the canvas | all categories | Quick proof: open =dist/specimen.html= — one self-contained page (renderer + the four procedural generators + the open-peeps & transhumans bundles inlined) that renders *every style* down the same seed set, so you see one identity wear each art style, plus a global seed input that updates them all at once. Pixabots rasters render from =../packs/pixabots/webp/= on disk. Rebuild it with =node test/build-specimen.mjs=. Tests: =node test/avatar.test.mjs= (90 checks).
