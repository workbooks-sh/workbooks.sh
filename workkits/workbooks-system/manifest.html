A *knowledge* toolkit for an agent that is itself running inside a Workbooks runtime. It carries no new CLI binary of its own — =wb= is already on PATH in the runtime — only the org skill files that teach the agent the platform it lives in: what the pieces are, the invariants it must not break, and how to author, publish, and reason about workbooks from the inside. The agent's reality this toolkit is written FOR: - One tool surface — a WASM-sandboxed shell. Capabilities arrive as commands on PATH, never as new tool-registry entries. - WASM commands only — no node / python / cargo / native binaries. Need a capability that isn't there? It goes through a compiler lane, not an install. - Files via =vfs_read= / =vfs_write=; the workdir is a tenant git repo. - =wb= available as a command (in-process; same modules the runtime uses). - Network only when granted, via curl-like =fetch=; every action is wall-clock bounded; your commits are public. Host-level operations — provisioning machines, building/pushing the runtime image, =work deploy=, editing host engine code, =fly=/cloud lifecycle — belong to operators OUTSIDE the runtime. They are out of scope for an in-runtime agent; this toolkit names them only to draw the line.
