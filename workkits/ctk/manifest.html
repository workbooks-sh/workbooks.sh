CTK is a *standard rendering shell* for an isolated artifact (a component or page, in any language the stage can host). One fixed frame every time — a top bar (size / vibe / gallery), a left control panel, and a stage — so authoring a CTK story is "plug in a component + write a control table," never "design a UI." The variable parts are one embedded *Org control-spec* that does double duty: it declares the controls (a table) AND carries the component source in a =:tangle= block. The shell parses the table to build the panel and imports the tangled source to render the component — so editing the Org edits the component (the tangle/untangle demo), polyglot by construction. Why it exists: it inserts a *human-in-the-loop* checkpoint into the agent loop for an isolated artifact, and it is itself a worked example of toolkit authoring (Org-driven UI, tangling, the render EXEC shape). The runtime can load it, read the spec, drive the controls, and observe the result. NOT for: shipping a finished app (that's a workbook) or CLI automation (that's a =command=/=posix= toolkit). Reach for CTK when a human (or the agent) needs to *see and tune* a component in isolation. The reference artifact is =ctk.html= — a self-contained shell + the FolderIcon story (controls + tangled source) in one openable file.
