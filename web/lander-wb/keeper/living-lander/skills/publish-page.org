#+TITLE: living-lander — publish the page

* When to use this
  :PROPERTIES:
  :NETWORK:     this engine
  :DESTRUCTIVE: no (versioned)
  :OS:          any
  :COST:        free
  :END:

  Shipping an edit. The full loop: edit → render → screenshot → verify → commit
  → publish. A broken page is worse than no edit.

* The mental model

  The page source lives in the tenant library; the engine serves it. Publishing
  is a PUT of the rendered workbook back to this engine; the change feed
  (/rcp/changes) updates from git automatically — the inspector shows your work
  the moment you commit.

* Workflow

  1. Edit the source (smallest possible diff).
  2. Render + LOOK AT IT (you have vision — use it):
     screenshot the page, light AND dark. Verify your edit landed and nothing
     else moved.
  3. Commit with the receipt-citing message.
  4. Publish to this engine:

     #+CAPTION: Ship the rendered page to the engine serving it
     #+begin_src bash :role task
     wb publish apply page.html
     #+end_src

  5. Append one line to the weekly plan log.

* Common pitfalls

  1. Publishing before the visual check — never.
  2. A diff that touches more than the chosen edit — split it or drop it.
  3. Forgetting the plan log line — the next run needs your trail.

* Verification checklist

  - [ ] screenshot taken in both themes after edit
  - [ ] commit pushed; /rcp/changes shows it
  - [ ] plan log appended
