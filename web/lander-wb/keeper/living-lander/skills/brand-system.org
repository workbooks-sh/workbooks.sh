#+TITLE: living-lander — brand system

* When to use this
  :PROPERTIES:
  :NETWORK:     none
  :DESTRUCTIVE: no
  :OS:          any
  :COST:        free
  :END:

  BEFORE any edit that touches visuals or copy. The component library at
  =assets/components.html= is the north star — open it, use ONLY its primitives.

* The mental model

  TWO VOICES: every HUMAN claim (Newsreader serif, editorial) pairs with a
  MACHINE receipt (Spline Sans Mono, a real command/output). The trio
  (#00ff44 / #0080ff / #ff0066) is theme-constant; neutrals flip light/dark.

* Workflow

  1. Confirm the library is present:

     #+CAPTION: The north star ships inside this toolkit
     #+begin_src bash :role pre
     test -f ../assets/components.html && echo "components.html present"
     #+end_src

  2. Pick primitives FROM it: buttons (no strokes, solid fills), chips,
     appframe, cells, terminal block, ascii field, hairline grids.
  3. Hard bans: gradient text · thick black outlines · fabricated
     numbers/users/praise · em dashes in copy · buzzwords (seamless, supercharge,
     enterprise-grade) · removing the inspector, CTA, or ground rules.

* Common pitfalls

  1. Inventing a new component when a primitive exists — extend, never fork.
  2. Using raw trio colors for body text on light (use the -text variants).
  3. Breaking dark mode — every change must hold in both themes.

* Verification checklist

  - [ ] edit uses existing primitives/tokens only
  - [ ] both themes screenshot clean
  - [ ] no banned patterns introduced
