* Deploy the runtime locally
  :PROPERTIES:
  :MATURITY: ships-today
  :EVIDENCE: cli/src/deploy/mod.rs:82
  :OWNER:    cli
  :END:

=work deploy= is the *user* tool for running the runtime image for your own use —
not a platform-release mechanism. Locally it converges =deployment.org= against a
container-engine seam: =docker=, =podman=, or =krunvm= (whichever is on PATH).

#+begin_src bash
work deploy local        # scaffold ./deployment.org if absent, then apply
#+end_src

** Step by step
  :PROPERTIES:
  :MATURITY: ships-today
  :EVIDENCE: cli/src/deploy/mod.rs:32
  :SRC:      cli/src/deploy/mod.rs#DeployVerb
  :END:

1. =work deploy init local= — scaffold =deployment.org=.
2. =work deploy secrets set KEY=VALUE= — store declared secrets (0600, under the app
   dir; never written into =deployment.org= or any image).
3. =work deploy validate= — coherence check, including declared-but-unset secrets.
4. =work deploy apply= — converge to the declared state.
5. =work deploy status= / =work deploy logs= — inspect / tail.
6. =work deploy down= — tear it down.

=work deploy doctor= reports which engines, recipes, and secrets are present.

** krunvm caveat
  :PROPERTIES:
  :MATURITY: partial
  :EVIDENCE: cli/src/deploy/mod.rs:471
  :CAVEAT:   krunvm can't deliver the kit's secrets env yet — use docker/podman locally, or a cloud provider, when secrets are required.
  :END:
