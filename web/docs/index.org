#+DESCRIPTION: How to write, run, and publish a Workbook.

* Workbooks
  :PROPERTIES:
  :WORKBOOK_VERSION: 1
  :END:

A workbook is a single =.org= file that carries its own code, data, and a query
interface over both. You author it in Org mode; the runtime renders it, runs its
components in-WASM, and ships a self-contained =.html= artifact. No build
pipeline. One file in, one file out.

This page is a workbook. It was rendered by the same engine that runs yours.

** What lives in the file

A workbook is plain Org with one convention — a =:WORKBOOK_VERSION:= property
on the top-level heading. Everything else follows standard Org structure:
headings, prose, source blocks, and =:PROPERTIES:= drawers for configuration.

#+begin_src org
,#+TITLE: My Workbook

,* My Workbook
  :PROPERTIES:
  :WORKBOOK_VERSION: 1
  :END:

Prose goes here. Source blocks are components.
#+end_src

Source blocks with a known language compile to WASM components. The engine
wires them together; you write business logic, not glue.

#+begin_src javascript
export function greet(name) {
  return `hello, ${name}`;
}
#+end_src

** The render path

The OQL kernel (=oql.wasm=, embedded in the runtime binary and in the desktop
app) reads the Org source and produces HTML. The kernel runs in-WASM — there is
no native code path for rendering, just the component the engine loads.

#+begin_src text
org source → OQL kernel → rich HTML → self-contained .html artifact
#+end_src

The same kernel runs locally in the desktop app, in the server runtime, and at
publish time. There is no difference between preview and production output.

** Publishing a workbook

=wb publish= renders a workbook and ships the HTML to a provider. One command,
one URL.

*** scaffold the config

#+begin_src sh :exports code
wb publish init
#+end_src

This writes a =publish.org= next to your workbook:

#+begin_src org
,* publish :publish:
  :PROPERTIES:
  :PUBLISH_TARGET:  cloudflare-pages
  :PUBLISH_PROJECT: my-project
  :PUBLISH_DOMAIN:  my-project.pages.dev
  :PUBLISH_TITLE:   My Workbook
  :END:
#+end_src

Supported targets: =cloudflare-pages=, =gh-pages=, =self-hosted=.

*** validate and deploy

#+begin_src sh :exports code
wb publish validate        # coherence-check — no network
wb publish apply index.org # render + ship → prints live URL
#+end_src

The HTML is written to =.publish_out/index.html= locally, then the provider
receives it. For Cloudflare Pages, =wrangler= must be on =PATH= and
authenticated (=wrangler login=).

** The deploy-kit

=wb publish= is distinct from =wb deploy=. Deploy stands up the full runtime
(the Elixir server, WASM loaded on the BEAM, agents, the control plane) in a
container — local or cloud. Publish is lighter: render the workbook, ship the
HTML. Use publish for static sites and documents; use deploy when you need the
full runtime behind a URL.

| verb              | what it runs          | when to use                   |
|-------------------+-----------------------+-------------------------------|
| =wb publish=      | OQL kernel only       | static page, docs, one workbook |
| =wb deploy local= | full runtime (local)  | dev, the desktop daemon       |
| =wb deploy apply= | full runtime (cloud)  | production server             |

** Running locally

#+begin_src sh :exports code
git clone https://github.com/workbooks-sh/workbooks.sh
cd workbooks.sh/runtime
mix deps.get && iex -S mix
#+end_src

The desktop app ships the OQL kernel and renders workbooks offline with no
server. Download it from the releases page on GitHub.
