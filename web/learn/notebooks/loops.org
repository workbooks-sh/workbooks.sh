* the agent, defined in org

The agents lesson says an agent is a model, in a loop, with tools. In this
ecosystem the definition is a document. Here is one: who the agent is, what
it can reach for, and what it is trying to do, in a properties drawer the
kernel parses canonically.

#+begin_src org :name agent
* doc-finder                                  :agent:
  :PROPERTIES:
  :MODEL: sim-one
  :TOOLS: search, read, done
  :GOAL:  how does the engine split work?
  :END:
#+end_src

* read the definition

The loop never hardcodes its agent. It reads the document.

#+begin_src js :action read the agent definition
const def = nb.oql.headlines(nb.org("agent"))[0];
nb.agent = { name: def.title, model: def.props.MODEL, tools: def.props.TOOLS.split(",").map((s) => s.trim()), goal: def.props.GOAL };
print("agent:", nb.agent.name);
print("tools on the path:", nb.agent.tools.join(", "));
print("goal:", nb.agent.goal);
#+end_src

* the loop itself

One turn: the model looks at history and picks a tool; the loop runs the
tool and appends the result. That is the entire construct. The simulated
model here stands where a real model call would go; the loop cannot tell
the difference, which is the point.

#+begin_src js :action run the loop until done
if (!nb.agent) throw new Error("read the agent definition first");
const tools = {
  search: (q) => `three results for "${q}": doc-a, doc-b, doc-c`,
  read: (d) => `contents of ${d}: the engine coordinates, the sandbox computes`,
  done: (answer) => ({ finished: true, answer }),
};
const model = (history) => {
  const last = history[history.length - 1] || "";
  if (!last) return { tool: "search", args: [nb.agent.goal] };
  if (last.includes("three results")) return { tool: "read", args: ["doc-b"] };
  return { tool: "done", args: ["the engine coordinates, the sandbox computes"] };
};
const history = [];
for (let step = 1; step <= 6; step++) {
  const call = model(history);
  const result = tools[call.tool](...call.args);
  print(`step ${step}: ${call.tool}(${call.args.join(", ")})`);
  if (result.finished) { print("answer: " + result.answer); break; }
  history.push(String(result));
}
#+end_src

* why long-running is the whole point

Run the loop again: it starts from nothing every time. That is the industry
default: summoned, evaporated, amnesiac. A real agent keeps memory between
runs. Here, memory is what the previous notebook built: an org repository.
Run this twice and watch the second run skip the work.

#+begin_src js :action run with memory kept
nb.memory = nb.memory || [];
if (nb.memory.length) {
  print("memory has " + nb.memory.length + " entry - resuming, not restarting");
  print("answer recalled: " + nb.memory[0]);
} else {
  nb.memory.push("the engine coordinates, the sandbox computes");
  print("worked for it this time. run this again and watch the difference.");
}
#+end_src

#+begin_recipe
Implement a long-running agent loop driven by an org definition.

Build: a loop that reads its agent from an org headline with a properties
drawer (MODEL, TOOLS, GOAL), then repeats: call the model with the run
history, execute the tool the model picked from the registry, append the
result. Stop when the model calls done() or a wall-clock timeout hits.
Never an iteration cap.

Requirements:
- The agent definition is a document, parsed canonically; changing tools
  or goal means editing org, not code.
- Tools are plain named functions: input in, result out.
- Memory survives between runs in a writable org layer; on start, read it
  and resume rather than restart.
- Log each step as: step N, tool, args, result, so a human can replay it.

Acceptance: run it twice on the same goal; the second run does less work
because it remembered.
#+end_recipe
