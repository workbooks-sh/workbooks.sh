what you build

One file is the whole app.

A workbook isn't a project folder or a repo full of config. It's a single portable file that carries the code, the data, and the interface together — open it, run it, share it, own it. Like a PDF, except the document is a working app.

code

Real code, many languages

Write actual software — Rust, Go, Python, JavaScript and more — that runs safely in a sandbox. Not a watered-down builder; the real thing.

data

Its own data, inside

Every workbook can carry its own database. The data travels with the app, queryable in place — nothing to provision, nothing to connect.

interface

An interface that ships

The UI is part of the file. Publish a workbook as one self-contained page that opens in any browser — no server required to view it.

on your machine

It runs where you do.

Your apps run locally, offline, on hardware you control — not rented from a service that bills per request and has to stay alive for your app to keep working. Bring your own API keys and pay only for what you actually use.

  • ⌂Offline-first.The desktop app embeds the runtime, so your workbooks open and run with no server and no internet.
  • $Cheaper by design.One runtime built on Elixir runs many apps on one box — no sprawl of metered functions each with its own bill.
  • ⛁Your keys, your data.Plug in your own model provider. Nothing has to leave your machine for an app to work.

people + agents

You and your agents, building together.

Because a workbook is a sandbox, an agent can write real code and actually run it — with no way to break out. Agents don't just answer here. They build: author a workbook, test it, ship it. You and your agents work on the same files and the same data.

  • ▷They run what they write.An agent's code executes in the same sandbox you trust — safe to let it try, fail, and fix.
  • ≋Context stays put.Code and reasoning live side by side in one file, so an agent keeps its place and drifts less the longer it works.

own it · ship it

Keep it forever. Ship it anywhere.

Every workbook is one self-contained file that opens in any browser — no service that has to stay alive for it to work. When you're ready, send the same file to a container, your own server, or the cloud with a single command. Your app, your infra, your terms.

  • ⊞Portable by default.One file is the whole app. Email it, commit it, archive it — it still runs in a year.
  • →Deploy in one command.Run the same workbook locally or push it to where you want it. No pipeline to assemble.
extend everything

The app is a factory, not a finished product.

Build your own commands, components, and capabilities — in any language — as sandboxed toolkits. Hack the runtime itself if you want to. It's all open, and an agent can author a toolkit for you on the spot.
