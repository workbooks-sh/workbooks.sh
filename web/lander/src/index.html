Workbooks turns a single workbook into a complete application — one Elixir engine running WASM on the BEAM, with a queryable single-file artifact at the center. No control plane to rent, no functions to wire together. Clone it and run it on hardware you own.

What it is

A self-contained runtime, not a framework you assemble. One Elixir engine supervises everything; your logic compiles to WASM and executes on the BEAM alongside it, so concurrency, fault isolation, and process supervision come from the platform instead of from glue you maintain. The whole surface is small enough to read in an afternoon and keep in your head after.

The workbook is the unit

A workbook is a single file that carries its own data, its own code, and a query interface over both. It is the source you edit, the artifact you ship, and the thing you query in place — no build pipeline turning one representation into three. Query it like a live backend, because that is what it is. Hand someone the file and they have the running app, not a link to one.

The serverless break

Serverless promised less to operate and delivered more to assemble — a function here, a queue there, a managed datastore, an identity provider, and a bill that grows with the diagram. Workbooks collapses that diagram into one runtime with one supervision tree. You trade a sprawl of vendors for a single process you can profile, restart, and reason about. Pay-as-you-go for what you run, and self-host the moment you would rather not pay at all. You stop operating a constellation and start running a program.

Built to self-host

Everything runs on infrastructure you control — your own machine, your own network. The engine is one OTP application with no hidden dependency on a hosted backend, so there is nothing to phone home and nothing to lock you in. Open source under a permissive license: audit the trust boundaries yourself, and fork the engine if you disagree. Small enough to read, which means small enough to trust and to fix.
