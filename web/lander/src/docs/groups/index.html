Studio

Group display & views.

A group's library page renders through a saved view. Each view picks a layout, a sort order, a grouping field, and which fields are visible. Admins can ship one or more views as shared options for the group; members can also save their own private views.

Layouts

Seven layouts are built in. Each is the same data, just a different shape.

  • List. Dense rows with title, type, tags, and timestamps. The default for most libraries.
  • Grid. Card grid with author and description. Best for portfolios and showcases.
  • Table. Tabular view. Choose which columns appear via fields.
  • Kanban. Columns grouped by type, tag, or author. Good for triage and pipelines.
  • Finder. Sidebar tree of groupings with a details pane. Best for deep libraries.
  • Gallery. One featured workbook above a grid. Good for highlighting a hero artifact.
  • Timeline. Chronological feed sorted by created or updated time.

From the Studio settings page

Open Group → Settings → Display. The section lists every saved view. Click a view to edit its layout, sort, grouping, and visible fields. Use the star to pick the default view — that's what new visitors see on first load.

Members see the same shared views as admins, plus any private views they've saved for themselves. Private views never leak to anyone else.

Defining views in a file

Display config can live in a views.toml file you check into source. Same shape as the settings UI; one [[view]] table per view. 

default = "triage"

[[view]]
id        = "triage"
name      = "Triage"
layout    = "kanban"
group_by  = "type"
sort      = { by = "newest", dir = "desc" }
fields    = ["title", "type", "tags", "author", "updated"]

[[view]]
id        = "feed"
name      = "Recent activity"
layout    = "timeline"
sort      = { by = "updated", dir = "desc" }

Valid values:

  • layout — list, grid, table, kanban, finder, gallery, timeline.
  • sort.by — newest, alpha, updated, views.
  • sort.dir — asc or desc.
  • group_by — none, type, tag, author.
  • fields — any of title, type, tags, author, updated. Omit to take the default set.

Pushing from the CLI

Once the CLI's group push subcommand lands, you'll sync the file with one command: 

workbook group push views.toml --group pricing-research

Until then, upload the file from the Display section in Studio — same parser, same result.

Status. The views.toml format described here is the target shape and is what the upload + CLI flows will accept once those land. The settings UI works today and writes to the same broker storage.
