# 3w

`3w` (WWW) gives an agent the open web with no API keys and no per-call cost. It is not a generic browser wrapper: `search` is native multi-engine (DuckDuckGo + Bing + Brave + Mojeek, merged by cross-engine consensus) and `read` is a Chrome-impersonating fetch that falls back to a real JS render only when a page actually needs it. Zero keys gets you a fully working research loop from inside the sandbox.

## When to reach for it

Reach for `3w` whenever a workbook or agent needs to find and read pages on the live web. Use it instead of `curl` — raw fetches are bot-walled and can't run JavaScript, and an agent shouldn't have to know a domain before it can read it. `search` is the on-ramp: search first, then read the URLs it returns.

## Example

```
3w search "wasm component model 2024 spec"
# pick a URL from the results
3w read https://example.com/spec --render   # --render only where a page needs JS
```

## What it grants

- Keyless multi-engine web search (Google is intentionally absent — its wall is JS/behavioral and not cheaply recoverable; widen engines instead).
- Clean readability extraction of a URL to markdown, JS-aware.
- Optional proxy routing (`WB_WEB_PROXY`) and optional Google-grade coverage (`SERP_API_KEY`) — both optional; the default needs no keys.

## Maturity

Experimental. Search and read are live. The headline goal — crawl/harvest a research run into a portable workbook context repository — is still landing (the `crawl` / `harvest` / `repo` verbs are in flight); don't present them as shipping yet.
