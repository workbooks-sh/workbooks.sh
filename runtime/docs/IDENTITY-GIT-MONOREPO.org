#+TITLE: Identity → Sharing → Composition — the substrate plan
#+DATE: 2026-06-07
#+STATUS: PLAN (source of truth; supersedes scattered notes)

The whole substrate reduces to a few primitives. This doc inks the model + the
phased build. Guiding rule throughout: *least code, lean on existing libraries
and CLIs* (shell to =jj=/=rad=/=git= like we shell to =cargo=/=bun=; reuse crypto +
did + atproto libs; reimplement nothing we can call).

* The primitives (everything is one of these)
- *Container* — a single =.html= file bundling data + the runtime to query it.
  Containers nest (a container's file tree can hold containers). Fractal.
- *Workbook* — a packed container. The artifact. Facets, not types: document /
  context-repository / file-store / agent-container / backend — set by content +
  which runtime pieces are embedded + whether something inside is active.
- *Workspace* — the unit a user/org loads + unloads. A collection. Two forms:
  - PACKED = workbook(s)/containers, DID-referenced, compact, runnable.
  - UNPACKED = a flat source tree (org + readable SQL + the manifest) — the
    *monorepo* projection that syncs to GitHub.
- *Library* — the TOP layer, scoped to ONE identity (a user OR an org), never
  shared. NOT a folder — an ACCESS GRAPH: the set of every workspace + workbook
  that identity can reach, resolved ACROSS orgs, workspaces, and servers. The
  Library IS the permission / scope / policy layer (it disassembles into "what
  this identity can touch"); the workspace/workbook are what it grants access to.
  See "The Library" below.
- *Monorepo* — NOT a separate thing and NOT the Library: the unpacked,
  git-backed PROJECTION (backup + sync + portability) of a workspace's content
  to a repo (local FS / GitHub / Radicle). It's how Library content leaves the
  runtime to be backed up + shared; the live access model stays in the Library.
- *Manifest* (=.workbooks/workspace.org=) — declares members (by DID or path) +
  the logical structure. The structure lives in CONFIG, decoupled from the file
  tree, so reorganizing the monorepo = editing the manifest, not moving files.
  The same workbooks project into different layouts via different manifests.
- *DID* — the reference scheme. A member is embedded (vendored) OR referenced by
  DID (resolved on demand). Embed = portable but bloats; reference = lean but
  needs resolution. Workbook scale → embed; monorepo scale → reference.

* Pack / unpack (the codec, not a build tool)
- =pack=   : source tree + manifest → workspace (re-weave each member, resolve
  DID refs). Generalizes =book seal= over a manifest.
- =unpack= : workspace → flat source tree + manifest (for git/GitHub). Extends
  unbundle to write files to disk.
- The agent's WORKING form IS the unpacked tree — literally the workflow workdir
  + scratch we built. It edits source, then =pack= (= =book seal=) to store/share.
  Load/unload a workspace = unpack/pack.
- *Unpacked SQLite is readable source* (SQL dumps / org tables), not binary
  blobs — the point of the unpacked form is that GitHub shows something legible
  and diffable.
- Orchestrated by the org-workflow DAG, NOT Bazel. Revisit Bazel only at real
  multi-language / huge-graph / remote-cache scale.

* Tangle build step — three projections of one workbook (locked)
*A workbook RUNS WebAssembly, not source.* So pack has a compile stage, and the
same workbook projects three ways depending on where it's going:

- *source* (=wb pack=) — the build INPUTS (=.rs=, =Cargo.toml=, readable assets).
  What syncs to GitHub + what a human diffs. No build outputs.
- *runnable* (=wb pack --build=) — compile each component to =.wasm=, ship the
  OUTPUTS, DROP the source inputs. "Build files don't enter the runnable artifact
  unless they're WebAssembly." Non-source assets (docs, html) stay.
- *archive* (=purpose: :archive=) — everything (source + outputs + session).

- *Real, not stubbed* (=Workbooks.Build=): compiles with the toolchains actually
  present — =cargo component= for crates, =rustc --target wasm32-*= for a lone
  =.rs=. A component whose toolchain is missing (JS needs =jco=) is reported
  UNBUILT with the reason, never faked. =Workbooks.Build.build_input?/1= +
  =build_output?/1= are the classification both pack + the git rail consult.
- *Compile-time vs run-time / local vs cloud.* COMPILE needs the host toolchain
  (dev box, or a CI/deploy step) — it is NOT a runtime dependency. RUN needs only
  a wasm runtime: a core module runs via wasmtime (=CommandRegistry=, like
  jq/grep), a WIT component runs in a =Wasmex= Instance (the Dock, like the OQL
  kernel). So a workbook compiles once (anywhere with the toolchain) and its
  =.wasm= runs in any Instance — local engine or cloud =bn-engine-agents=,
  identically. The cloud runtime image need not carry rustc; it carries the
  prebuilt =.wasm=.

* Public / private boundary — privacy by DEFAULT (locked)
*Sharing exposes WORK, never the session that produced it.* Telemetry, agent
memory, scratch thinking, signing keys, issue-tracker exports — none of it
travels when work is committed, packed, or checked out, unless the owner
EXPLICITLY opts in. This is the default that prevents the leak class we already
hit (beads task data pushed to GitHub — potentially revealing/secret content).

- *One boundary, every egress.* =Workbooks.Private= is the single source of truth
  for what is personal/session data; Git, Bundle, and Library all consult it, so
  the line can't drift between paths. Two kinds:
  - FILES/DIRS in a working tree — =scratch/=, =.workbooks/= (keys), =.beads/=,
    =.claude/=, and the session sidecars =_steps.jsonl= / =_status.json= /
    =_telemetry.db= / =_ledger.json= / =_*.{jsonl,json,db}=. Emitted as the
    git-ignore set written into every tenant repo automatically, so neither agent
    nor human has to remember it (the "automated public/private ignore" — without
    a real FS this is too error-prone to leave manual).
  - VFS VOLUMES in a container — only =workspace= ships; =memory= (agent
    long-term memory) and =tmp= are stripped from a bundle on egress
    (=VFS.public_only/1=).
- *Opt-in is explicit.* =include_private: true= (Bundle) / future =--include-private=
  flags, same shape as the identity toolkit's key export. Default is always the
  safe one.
- *Provenance still ships.* The signed manifest is EMBEDDED in the artifact html
  (=Workbooks.Manifest=), so a shared workbook stays verifiable — but the
  =_ledger.json= (session telemetry, sealed) stays private. Proof travels; the
  session log doesn't.
- *Why it's load-bearing.* The whole Library model is "share the contents, never
  the Library." That only holds if the contents themselves are clean by default.
  Privacy-by-default is the precondition for safe sharing, not an add-on.

* The Library (the identity-scoped top layer) — locked
*A Library is what one identity (user OR org) can reach — an access graph, not a
folder.* It is the answer to "what work is mine / my org's, and where does it
live." Never shared between identities; sharing happens to its CONTENTS, by
manifest + C2PA, on egress.

- *It disassembles into access, not files.* A Library resolves an identity's
  workbooks + workspaces ACROSS every org it belongs to, every workspace, and
  every server (this engine or another) — into one extensible map of permission
  scopes + policies. Membership in N orgs ⇒ the Library is the union of what
  those memberships grant, with each item carrying its own scope. So the Library
  IS the access-control layer over workbook files; the existing per-request
  tenant scoping (Guardian) + the WASM capability Policy are its enforcement
  points, not a separate system.
- *Monorepo = the Library's backup/sync, not the Library.* "Back up all my work
  to a repo" = project the Library's workspaces to their unpacked git form
  (=Workbooks.Git= per-tenant repo → GitHub / Radicle / local FS). The repo is
  durable + portable + diffable; the Library stays the live access graph. One is
  the photo, the other is the room.
- *Checkout (load/unload).* Pull a workbook/workspace OUT of the Library into a
  working context (the unpacked workdir + scratch we already run) and check it
  back IN when done — borrow/return, exactly =unpack=/=pack=. On the way out it
  can be shared through the manifest/sharing rails; on the way back its ledger +
  signature update.
- *C2PA is the connective tissue.* Every item in a Library is did:key/C2PA-linked
  (=Workbooks.Manifest=, the signed ledger), so access, provenance, and sharing
  are ONE fabric: a checkout is attributable, a shared artifact verifies
  standalone, and "who may touch this" rides the same identity that signs it.
- *Build order.* Access model first (Library = a manifest/index over the tenant's
  workspaces + an access-resolution fn over Guardian scopes + Policy), THEN
  cross-workbook OQL query-through across a Library's members. Pack/unpack
  (=Bundle=) + signing (=Manifest=) + git backup (=Git=) already exist — the
  Library is the index + access layer that composes them, not new machinery.

* Identity (auth)
- Already wired: *BetterAuth* issues JWTs (login, OAuth, API keys); *Guardian*
  verifies via JWKS + scopes every request to a tenant (=organizationId=). That
  scoping IS data sovereignty.
- Deploy-kit knob: =auth: workos | clerk | native | bluesky=. Guardian never
  changes — only the issuer/JWKS swaps.
  - desktop → WorkOS ; brandnana (cloud) → DECIDE (Clerk vs WorkOS) ;
    public-federated → bluesky (see Sharing) ; native + own 2FA → later.
- *Agent DIDs*: extend minting from tenants to AGENTS (and sessions). Every agent
  edit is signed by its agent DID. Basis for the ledger below.

* Sharing — two rails (map to pack/unpack)
- *Source rail → GitHub (working layer = JJ).* The UNPACKED monorepo syncs here.
  JJ is the working VCS (cheap branches, auto-rebase, an op-log that is itself
  provenance); it writes git objects, so GitHub + Radicle work unchanged. GitHub
  integration = a multi-tenant *GitHub App* (one install per deployer; their
  users connect through it). Radicle (=rad= CLI) layers on the same git objects
  for P2P share by DID — stacks with JJ, doesn't conflict.
- *Artifact rail → ATproto (public) / self-host (private).* The PACKED workbook
  publishes here, C2PA-signed.
  - PUBLIC = Bluesky/ATproto. Sign in with Bluesky (ATproto OAuth, DPoP-bound
    tokens) → you are =did:plc:…= → publish a workbook RECORD to your PDS
    (=uploadBlob= + ref; records cap ~256KB so real workbooks always go as
    blobs). Bluesky is auth + DID + publish target in one.
  - PRIVATE = self-host: =did:web= on your domain + your deploy-kit engine.
  - Deploy-kit MODE knob: public-federated vs private-sovereign.
- *DID bridging (load-bearing): the DIDs do NOT unify.* Signing uses =did:key=
  (Ed25519, engine-minted — already done). ATproto uses =did:plc= (secp256k1,
  PDS-held). A PDS will not accept a did:key. Answer: don't merge them —
  *C2PA-sign the bytes with the did:key BEFORE the carrier*, publish under the
  did:plc, attach issuer DID + record CID as a =PublishedAtproto= assertion. The
  C2PA manifest BINDS the two (provenance, not authn). No central signer, no PKI,
  no revocation registry day one.

* Composition (cross-workbook)
- Two coupling modes; the runtime is the BROKER, the manifest declares the graph:
  - CO-PACKED (tight) — workbooks that must stay paired → same container → talk
    in-process.
  - REFERENCED (loose) — e.g. one context-repository referenced by N agent
    containers → each holds a DID ref → the runtime mediates over its WIT /
    protobuf component layer (typed cross-workbook calls are native to the
    component model). N agents → 1 shared context repo → N artifacts, edges in
    the manifest.

* The signed agent ledger (the spine — where it all converges)
*telemetry + agent DID + C2PA signing = one capability.*
- Plain now (Phase 0): per-session =_telemetry.db= with task + step events.
- Hardened later (Phase 2): each entry hash-chains the prior (tamper-EVIDENT),
  signed by the agent DID (ATTRIBUTABLE), optionally runtime-witnessed + anchored
  to the carrier (a git/JJ commit or an ATproto record → externally VERIFIABLE).
- Payoff: pinpoint a session log → the agent DID → trace every file + edit it
  made, in order. Detect a prompt injection and its full blast radius after the
  fact — and neither agent nor user can rewrite the record. Infallible
  provenance, built into the substrate. JJ's op-log reinforces it.
- Same table, two stages — like "Guardian stays, the issuer swaps."

* Validation-gated merges (org validations × JJ × sub-agents)
The org-mode validations (the workflow's =:done-when:= commands + =#+begin_src
:check= blocks — "unit tests for org mode") become the SEMANTIC layer of JJ's
conflict resolution. JJ auto-resolves TEXT; the org specs resolve MEANING.
- Concurrent sub-agents work on JJ branches; JJ auto-rebases/merges the bytes.
- After a merge, the *predetermined* org specs run as the MERGE GATE: a change
  that violates a declared spec FAILS even if it merged cleanly as text →
  rejected / re-resolved / flagged.
- So sub-agent concurrency (JJ branches) + validation (workflow specs) + the
  signed ledger (who changed what, attributable) are ONE mechanism: agents fan
  out, the org specs arbitrate correctness, the ledger records it, JJ's op-log +
  the hash-chain make it all replayable + tamper-evident.
- This is where sub-agents get *tested + evaluated* against the org substrate
  itself. Build it at the Phase 2 (JJ) ∩ Phase 3 (sub-agents) ∩ ledger
  intersection — predetermined specs as the conflict arbiter.

* The throughline
identity (tenant + agent DIDs) → sovereignty (per-tenant git + signing) →
sharing (source→GitHub/JJ/Radicle, artifact→ATproto/self-host, C2PA) →
composition (manifest-driven workspace↔monorepo, cross-workbook via the runtime
broker) — with the signed agent ledger proving every step.

* Phased build
- *Phase 0 — Telemetry (the floor; in progress)*
  *Completeness mandate (the thing we always get wrong):* instrument at the
  CHOKEPOINTS, not the call sites, so nothing can escape by construction. The
  PRIMARY chokepoint is the component model itself:
  - *The Dock WIT interface (=wit/engine.wit=) — the core.* Every WASM component
    runs against a typed capability surface (=vfs-query=, =run-command=, =llm=,
    =net=, =session-info=) and the Policy already gates each import "by
    construction." So the *capability gate IS the telemetry point*: wrap the
    host's implementation of each Dock import → record cap, args, result,
    duration, error at the protocol boundary. A component can do NOTHING except
    through an interface we implement, so nothing escapes. Declarative — the
    component's WIT imports ARE the instrumentation manifest. This is the
    "WASM-based telemetry tool": observe at the same boundary we enforce. As more
    moves to components, telemetry is already there.
  - =Workbooks.Agent.exec_one= — the NATIVE exec path (System.cmd for exec:true
    agents, e.g. brandnana). Record tool, args, output, *exit_code*, *stderr/
    error*, duration. Catches "a bash call broke the system." [partly DONE:
    exit-code/error/duration + always-on =_steps.jsonl=]
  - =Workbooks.Llm.complete= — every model call: model, prompt/completion tokens,
    cost, duration, error.
  Plus the crash boundary (the spawn try/rescue → exception + stacktrace events)
  and validation results (each =:done-when:=/=:check=). Captured in the loop, not
  dependent on a caller wiring =on_step= — always-on whenever a workdir exists.
  *ADOPT, don't author* (less self-authored = better): use existing WASM
  observability — don't hand-roll capture/format/export.
  - =wasi-otel= (WebAssembly/wasi-otel) — the WASI STANDARD OTel interface for
    components. The component imports the wasi-otel WIT; the HOST provides it via
    a small host plugin (function-call into native, no network hop) that forwards
    to the OTel SDK (batching/export/protocol = the SDK's job). Parent-child
    spans across host↔guest + trace-context propagation. THIS is the WASM
    chokepoint — standardized, not self-authored. We author only the Elixir
    (Wasmex) host bridge.
  - =Dylibso Observe SDK= (dylibso/observe-sdk) — optional: recompile any wasm
    module to add per-function + memory-alloc tracing → OTel, zero guest changes.
  - Native exec path (System.cmd, not WASM) → the Elixir =:opentelemetry= SDK,
    fed by the =exec_tools= instrumentation (exit code/error/duration). Emits OTel
    directly since wasi-otel can't cover non-WASM.
  Everything → OTel → a *CLI feedback loop, NOT a dashboard*: a =wb telemetry=
  command reads the spans (local collector / sqlite exporter) → timeline of tool
  calls / exit codes / errors / cost per run + aggregates. Self-authored surface
  = the wasi-otel host bridge + the exec→OTel emit + the CLI. SPIKE FIRST:
  verify wasi-otel ↔ Wasmex/Wasmtime wiring before committing.
  0a verify live =_telemetry.db= [DONE] ; 0b chokepoint instrumentation
  (exec_one + Llm.complete → step/tool/error/cost) ; 0c the =wb telemetry= CLI +
  OTel spans ; 0d per-session db + cross-session index ; 0e wire into brandnana
  agent runs too.
- *Phase 1 — Auth profile* : deploy-kit =auth= knob (workos/clerk/native/bluesky),
  Guardian unchanged ; verify BetterAuth API-key + JWKS end-to-end.
- *Phase 2 — Git/DID + sharing + ledger-hardening*
  2a JJ working layer (shell to =jj=) ; 2b GitHub App (multi-tenant) ;
  2c C2PA signing on did:key ; 2d ATproto publish (Bluesky OAuth, blob+record) ;
  2e self-host did:web ; 2f Radicle =rad= P2P ; 2g harden the ledger
  (hash-chain + agent-DID sign + anchor).
- *Phase 3 — Composition* : the *Library* (identity-scoped access graph over the
  tenant's workspaces, resolved over Guardian scopes + Policy) ; manifest format
  (=workspace.org=) ; =pack=/=unpack= (generalize seal/unbundle) ; checkout
  (load/unload = unpack/pack) ; cross-workbook mount + OQL query-through ;
  runtime broker edges. Backup/sync to git is the monorepo PROJECTION, not the
  Library itself.
