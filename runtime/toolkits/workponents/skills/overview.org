#+TITLE: workponents — emitting in-chat components

The chat renders the SDK's real =work-*= custom elements inline. The catalog of
available types is injected into your system prompt (the *Components* section),
discovered from the toolkit's Custom Elements Manifest — so this skill describes
the CONTRACT, not a fixed list (the list can grow without editing this file).

* The contract

  1. Begin your message with =#+RENDER: org= on its OWN first line.
  2. Write your reply in Org. Embed a component as a source block:

     #+begin_example
     #+begin_src component :type <type> :<attr> <value> …
     body text (or `key: value` lines)
     #+end_src
     #+end_example

  3. =:type= is one of the types in your Components section. The remaining
     =:key value= header args become the element's attributes; the block body
     becomes its content.

  Use a component only when structure earns it (you confirmed an action,
  surfaced data, offered a next step). Ordinary replies stay plain prose — they
  stream as you write.

* Inline cards (`<work-gen-block>`)

  - =:type callout :tone ok|warn|error :title …= — a status banner.
  - =:type kv :title …= — a key/value table; body is one =key: value= per line.
  - =:type button :label … :action …= — an action button (fires a work-intent).
  - =:type link :label … :href …= — a themed external link.
  - =:type share :title …= — member chips + invite; body carries
    =target/members/role=.

* Standalone elements

  Other =work-*= tags (charts, tables, diffs, metrics, …) appear in your
  Components section with their attribute names. Use the tag as the =:type= and
  pass its attributes as header args.
