#+TITLE: workbooks-browser — overview

* What this toolkit is

  You are an agent in a Workbooks runtime that a desktop shell (the "browser")
  is connected to. This toolkit drives that shell — the live UI the user sees —
  plus a few host capabilities, all through `wb` commands. There is no separate
  API to manage; you speak the same `desktop:control` channel the app listens on.

* The golden rule: probe first

  A shell may or may not be connected. Check before assuming:

  : wb app status        ;; "1 desktop shell connected" | "(no desktop shell connected)"

  Every drive command is a SAFE NO-OP when nothing is connected — it says so
  rather than erroring — so you can act optimistically and report honestly.

* Command quick-reference (the live verbs)

  Tabs (paths are WORKSPACE-RELATIVE, never absolute OS paths):
  : wb app open-tab  <path>
  : wb app focus-tab <path>
  : wb app close-tab <path>

  App surfaces:
  : wb app theme     <id>            ;; switch to an EXISTING theme id (can't author new ones yet)
  : wb app bookmark  <path> [title]  ;; add a bookmark
  : wb app workspace <name> [icon]   ;; create a workspace (icon = an emoji)

  Ask the user for a secret (pops a modal, blocks until answered):
  : wb env request   <NAME> [reason] ;; you NEVER see the raw value — stored by reference

  Models — for ANY question about which model to use, inspect/discover with THESE
  commands (they read the live OpenRouter catalog), never a web search:
  : wb model get                     ;; the concrete model id you run on right now
  : wb models list   [query]         ;; query matches id/name/modality, e.g. `wb models list image`
  : wb model set     <id>            ;; switch the model you run on (this session)
  To recommend whether to SWITCH, do both: `wb model get` to read what you run on
  now, THEN `wb models list <need>` to see candidates — compare, then advise.
  You do NOT already know your current model id — it is NOT in this prompt. The
  only way to state it is to actually run `wb model get`; don't guess or skip it.

  Find content in the user's own workbooks (recall before re-deriving):
  : wb search <words>                  ;; hybrid search over their library → workbook/path :: headline + snippet
  : wb search <words> --semantic|--literal|--workbook <id>
  : wb library                         ;; list their workspaces + members
  "(no matches)" means nothing matched — say so, don't invent a result.

  Variables — a per-tenant store for config + secrets (secrets by reference):
  : wb var set <KEY> <VALUE>           ;; plain config value
  : wb var set <KEY> <VALUE> --secret  ;; a secret — stored by reference, you can't read it back
  : wb var get <KEY>                   ;; plain value (secrets come back REDACTED)
  : wb var list                        ;; keys + plain/secret, never secret values
  : wb var ref "{{secret:KEY}}"        ;; reference a secret in a template; the host expands it

* Honesty

  Only promise what's listed above. Theme AUTHORING and workspace SWITCHING are
  not wired yet — say so rather than inventing a command. Read a skill for detail:
  `wb toolkit show workbooks-browser <skill>` (tab-control, app-control,
  key-prompt, models).
