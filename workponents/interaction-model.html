interaction model · HTMX, copied onto work-*

HTMX's clarity comes from a small, orthogonal set of behavior attributes, local to the element (Locality of Behavior): you read a tag and know what it does. We copy that design wholesale onto work-* — same five axes, same names where they transfer — adapted only where we diverge from HTMX: we route through the Dock (not arbitrary URLs), render client-side (the server is optional, not the state engine), and have real compute (work-src → WASM) that HTMX deliberately refuses.

Two rules. (1) Copy HTMX's clarity — one attribute per axis, declarative, composable, read-on-the-element. (2) Uniform prefix w- mirrors HTMX's hx- — distinct from our work-/book- element prefixes, and collision-free (bare target=/swap= would clash with native <a target>).

The five axes — each a single attribute, exactly as HTMX shaped them:

trigger · w-on shipped

The full hx-trigger grammar, live on work-flow and work-src. every=/autorun are folded in as back-compat aliases. The from: event-listen is the unlock — declarative flow-to-flow choreography off our own work-flow-done events, no glue code.

<work-flow w-on="load"/>                          <!-- autorun on connect -->
<work-flow w-on="every 30s"/>                     <!-- poll (cron-lite)   -->
<work-src  w-on="visible once"/>                  <!-- lazy compute: run when scrolled into view -->
<work-src  w-on="click from:#go"/>                <!-- a button fires it  -->
<work-flow w-on="work-flow-done from:#ingest"/>  <!-- flow B chains off flow A -->
<work-src  w-on="input changed delay:400ms from:#q"/>  <!-- debounced live search -->

modifiers: once · changed · delay:<dur> (debounce) · throttle:<dur> · from:<sel> · target:<sel>. durations: 250ms 2s 3m 1h.

where we diverge — on purpose

1. Action targets a work, not a URL. HTMX's verb is an HTTP method to an endpoint; ours runs a work element through the Dock — same locality, no server assumption. 2. Reactive binding is the sugar. HTMX always swaps explicitly (hx-target); we keep w-target/w-swap for imperative placement but a book view also binds reactively via from= (signals) — take HTMX's clarity, not its mandatory round-trip. 3. We compute. The whole point HTMX won't touch.

Live proof: demo/triggers.html (w-on: load · chaining · visible) and demo/flow.html (the runnable flow). The trigger grammar is real today; the action/target/swap/data axes are the next increment, built the same faithful way.
