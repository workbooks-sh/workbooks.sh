workponents · search

Search is a query — not a bolted-on widget. Every keystroke runs a debounced query over the one shared engine (runtime DuckDB · browser DuckDB-wasm · an in-JS subset offline) — the same src/data layer that backs tables / data-viz / maps. The ⌘K palette adds in-WASM fuzzy ranking for commands the SQL LIKE can't express, and mixes them with live data hits. One token set, no build. Toggle the theme; everything re-themes.

theme match tier

The match tier swaps the ranking engine behind the SAME data path / API. floor = the engine LIKE substring filter. minisearch = a client-side MiniSearch index (lazy-loaded from a CDN) for ranked · prefix · typo-tolerant search. Try anlytics (typo) or eng (prefix) on each tier and watch the footer tag.

1 · Instant search — each keystroke is an engine query

Searches a registered source named people. Typing runs SELECT * FROM people WHERE name LIKE … OR role LIKE … OR city LIKE … LIMIT 8 in the engine — watch the rowCount change in the log + console (work-search-query).

2 · ⌘K command palette — fuzzy commands + live data, ranked

Press ⌘K / Ctrl-K (or click the trigger). Commands are fuzzy-ranked in-WASM (try tbl, thm); the People group below them is a live engine query over the same source. Arrow keys cross groups; ↵ selects.
