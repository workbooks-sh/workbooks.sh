workponents · tables

The table is a query — not a static grid. Sort, filter, and aggregate run in the engine (DuckDB on the runtime tier · browser DuckDB-wasm · an in-JS subset offline). The grid is a thin, virtualized viewport over the result. One engine backs tables, data-viz, and maps. Native custom elements, one token set, no build. Toggle the theme; everything re-themes.

theme

1 · Raw rows — register inline CSV, sort + filter in the engine

Click a header to sort (engine-side ORDER BY). Type in the filter box to filter (engine-side WHERE … LIKE). The data IS the source — an inline CSV the element registers on connect.

2 · Aggregate — the same engine, GROUP BY revenue per region

A different view over the same registered source — the aggregate is computed in the engine (SELECT region, count(*) , sum(revenue) … GROUP BY region). Sorting still pushes to SQL.

3 · Inline JSON — compact density, no declared columns

A second source from inline JSON rows; columns inferred from the result, types drive alignment, large set is virtualized.
