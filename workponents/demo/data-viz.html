workponents · data-viz

A chart is a view over a query — not a client-side data-wrangling widget. Aggregation, binning, and grouping run in the engine (DuckDB on the runtime tier · browser DuckDB-wasm · an in-JS subset offline); the element issues SQL and renders the result as zero-dependency, token-themed SVG. One engine backs tables, data-viz, and maps. Native custom elements, one token set, no build. Toggle the theme; every axis, mark, and tooltip re-themes from --work-*.

0 · KPIs — a number IS a 1-row aggregate query

SELECT sum(revenue) … FROM orders — the scalar is engine-computed, not hand-rolled in JS. The third tile carries an inline <work-spark> trend (its own query).

1 · Bar — revenue per region (GROUP BY in the engine)

The aggregate lives in the SQL: SELECT region, sum(revenue) AS revenue FROM orders GROUP BY region. The element just maps x="region" / y="revenue" off the result to bars. Hover a bar for the tooltip; click emits work-point-select.

2 · Line — revenue trend by day (GROUP BY day, engine-computed)

Same source, a different query: GROUP BY day over the registered table. The line maps the ordered day buckets to points.

3 · Area + multi-series — units & revenue by region

Two value columns from one aggregate → two series, one legend.

4 · Pie — share of revenue by product

GROUP BY product; slices map to the value column, % computed from the result.

5 · Scatter — units vs revenue per order (raw rows, no aggregate)

When the query returns raw rows the chart plots them directly; numeric x gets a numeric axis.

6 · Sparklines — a trend inline, each its own query

No axes, no chrome — <work-spark> sits inline. Revenue/day   orders/day
