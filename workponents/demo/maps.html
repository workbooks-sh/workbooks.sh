workponents · maps

A map is a spatial view over a query — points and regions come from query rows (lat/lon/value columns), not a hand-fed GeoJSON blob. Spatial filtering and aggregation run in the engine (DuckDB on the runtime tier · browser DuckDB-wasm · an in-JS subset offline). The base layer is an abstract themed projection — zero deps, no tile provider, no network; real basemap pixels are a keyed exception reached through the Host seam. One engine backs tables, data-viz, and maps. Toggle the theme — the whole map re-themes from --work-*.

engine

The POWERED tier is MapLibre GL, lazy-loaded from a CDN ESM at runtime (never bundled). With no Host tile broker it draws a token-themed blank/vector style — the SAME features from the SAME engine query. Force floor (or block the CDN) and the zero-dep SVG projection still renders.

1 · Points — one marker per query row (size = population)

An inline-JSON source registered as cities; the map runs SELECT * FROM cities, reads the lat/lon/pop columns, and projects each row. Pan (drag), zoom (wheel / + −), click a point to select.

2 · Heat — the same rows as graduated density blooms

Same registered source, mode="heat"; intensity scales with the engine-supplied pop value. No shader, no dependency.

3 · Choropleth — aggregated BY REGION in the engine

The map runs SELECT region, avg(lat), avg(lon), sum(pop), count(*) … GROUP BY region — the aggregation happens in SQL, the element just binds the result. With no GeoJSON the standalone floor draws graduated proportional bubbles at each region's centroid.

4 · Choropleth — region polygons bound to the aggregate

Same engine aggregate, now bound to an inline GeoJSON of macro-regions by key="region" → fill scales with sum(pop) (token-only via color-mix). The GeoJSON gives shape; the data still comes from the query.
