workponents · files

A file is a content-addressed row — name, path, type, size, modified, content-hash. So a drive is just a file browser over a query on the same engine that backs tables, records, and data-viz — not a second filesystem. Selecting a file drives a typed inline preview: image & audio & video play inline (video rides the wavelet transcode path when docked), text shows inline, anything else degrades to a typed icon + metadata. Native custom elements, one token set, no build. Toggle the theme; everything re-themes.

The drive drives the preview

The drive on the left is a query over a registered assets source (each row = one file). Pick a file; its work-file-select event carries the row, and the page maps those columns onto the <work-file> on the right — which previews by type: a text file inline, an image by URL, and a typed placeholder for content that lives in the nexus (standalone, no Host → it shows the degraded card). Previews, standalone — text inline · image by URL · typed placeholder

Three <work-file> cards used on their own. Text and image-by-URL render with zero Host; the video card has only a path — its content lives in the nexus, so standalone it shows the typed placeholder + the “dock to transcode” note.

Add files — a drop is an insert

Drag a file (or click) — <work-dropzone> normalizes it into a content-addressed record (sha256 over the bytes) and emits work-file-add; here we register() the new row straight into the engine, and the drive above re-queries.
