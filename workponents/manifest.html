A *web-components* toolkit (=#+EXEC: component=): themed, framework-agnostic `<work-*>` custom elements. Like the glyphs toolkit, it ships zero-dependency JS that runs in a browser `<script>`, as an ES module, in Node, and in the runtime's wasm JS lane — and, because they are native custom elements, inside ANY workbook HTML with no build. The substrate (one architecture, many domains): - *Composition-as-source* — the element's definition is declarative source the artifact carries; preview ≡ source; agent-editable. - *In-nexus compute* — the element that renders the data also runs it (the workbook's SQLite VFS / wavelet render-core / the OQL kernel), brokered through the Dock; the same element runs in-page (sqlite-wasm) or on the runtime tier. - *One token set* — every element styles only from `--work-*` CSS custom properties, so one theme governs all domains AND the workbook artifacts. - *One Dock seam* — capabilities resolve `local` / `runtime` (RCP) / `kernel` behind the Host; the same element swaps providers per target. Parts that ship together — - =src/theme/tokens.css= — the design contract: the `--work-*` token set + the `[data-work-theme]` light/dark/brand presets. The single source of cohesion. - =src/core/element.js= — `WbElement`, the thin base class (shadow DOM, reactive attributes, token-aware styling, the render seam). Zero dependencies. - =src/core/variants.js= — the variant contract (cva-style: variant/size/tone as reflected attributes the component CSS targets via `:host([…])`). - =src/elements/<work-name>.js= — one element per file. `work-button` is the reference element (proves tokens + variants + theming + the base class). - =src/index.js= — registers every element + re-exports the classes. - =custom-elements.json= — the CEM catalog: every `work-*` tag → its attributes, events, and domain. The machine-readable source the agent-discovery, the theme-contract, and the evals all consume. Regenerate with `npm run cem`. - =demo/index.html= — the specimen / proof page (drops the elements in plain HTML, light + dark, no build). Relationship to toolkits: workponents IS a component-KIND toolkit (=#+EXEC: component=) — the themed UI tier over capability toolkits (a `work-table` is the view; the workbook's SQLite engine is a capability it consumes through the Dock). See docs/WORKPONENTS.md. Phase-0 follow-up (per docs/WORKPONENTS-AGENT-INTEGRATION.md §"The toolkit graph"): split the multi-node sub-graph — a static-asset core (tokens + base elements, no EXEC, shipped as dist/) + per-domain `#+EXEC: component` toolkits (the compute elements like work-table over the VFS, with `#+CAPS: vfs`). For P0 this single node carries `#+EXEC: component` so the runtime sees a wired toolkit (exec_checks no longer treats it as discovery-only); the per-domain split is the next increment.
