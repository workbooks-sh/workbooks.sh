#+TITLE: ffmpeg — scale · crop · pad video (resize for a target frame)
#+TOOLKIT: ffmpeg
#+SKILL: video-scale-crop
#+VERSION: 0.1.0
#+DESCRIPTION: Use when you need to change a VIDEO's dimensions — downscale to 1080p, crop a region, pad/letterbox to a target aspect (16:9 → 9:16 for social), or fit-inside a box. Covers the even-dimension rule, SAR/DAR pixel-aspect traps, and crop-vs-scale ordering.
#+TAGS: video scale resize crop pad letterbox aspect-ratio sar reels
#+STATUS: stable

* When to use this
  :PROPERTIES:
  :NETWORK: no
  :DESTRUCTIVE: no
  :END:

  A video is the wrong SIZE or SHAPE and needs reframing:

  - *downscale* a 4K master to a 1080p/720p delivery ceiling
  - *crop* a region (remove letterbox bars, grab a subject)
  - *pad / letterbox* to a target aspect (16:9 source → 9:16
    vertical canvas for Reels/TikTok, or square 1:1)
  - *fit-inside* a box without distortion
  - *recenter* a horizontal video into a vertical frame

  This is the VIDEO analog of [[file:image-ops.org][image-ops]] (still images). The
  filter syntax (=scale=, =crop=, =pad=) is identical; the gotchas
  differ because video adds the even-dimension codec requirement,
  the sample-aspect-ratio (SAR) trap, and the cost of re-encoding.

  NOT for: a still image ([[file:image-ops.org][image-ops]]); pure codec/format change
  with no resize ([[file:transcode-to-h264.org][transcode-to-h264]]); changing FRAME RATE
  ([[file:video-fps-speed.org][video-fps-speed]]).

* The non-negotiable rule: even dimensions

  H.264 / H.265 with the standard =yuv420p= pixel format CHROMA-
  SUBSAMPLES by 2 in each axis, so width AND height *must be even*.
  An odd output dimension errors out with
  =width not divisible by 2= (height: same).

  Always force even output:
  - =scale=W:-2= computes the other side AND rounds to even.
  - =scale=-2:H= the mirror.
  - For an explicit pair, make both even, or wrap an expression
    in =trunc(.../2)*2=.

* Workflow

** Inspect the source first (dims + pixel aspect)

  #+CAPTION: read width, height, SAR, DAR — SAR≠1 is the silent trap
  #+begin_src bash :role pre
  test -f "$1" || { echo "input file $1 not found"; exit 1; }
  ffprobe -v error -select_streams v:0 \
    -show_entries stream=width,height,sample_aspect_ratio,display_aspect_ratio \
    -of default=noprint_wrappers=1 "$1"
  # sample_aspect_ratio 1:1 = square pixels (normal). Anything else
  # (e.g. 40:33 from DVD/anamorphic) means stored dims ≠ display dims.
  #+end_src

** Downscale to a height ceiling (keep aspect, no upscale)

  =-2= rounds to even; =min(...)= caps so a smaller source is NOT
  enlarged (upscaling just wastes bitrate and softens the image).

  #+CAPTION: cap HEIGHT at 1080, width auto + even, never upscale
  #+begin_src bash
  ffmpeg -i input.mp4 \
    -vf "scale=-2:'min(1080,ih)'" \
    -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p \
    -c:a copy -movflags +faststart out.mp4
  #+end_src

  #+CAPTION: fit INSIDE 1920x1080 (whichever edge hits first), keep aspect
  #+begin_src bash
  ffmpeg -i input.mp4 \
    -vf "scale=1920:1080:force_original_aspect_ratio=decrease,scale=trunc(iw/2)*2:trunc(ih/2)*2" \
    -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p \
    -c:a copy -movflags +faststart out.mp4
  # second scale = even-rounding insurance; force_original_aspect_ratio
  # can yield an odd dimension on its own.
  #+end_src

** Normalize pixel aspect (the SAR fix)

  If =sample_aspect_ratio= isn't =1:1=, the stored pixels are non-
  square and players stretch on display. After any scale, reset SAR
  so downstream tools treat pixels as square.

  #+CAPTION: scale to a square-pixel 1280x720 from an anamorphic source
  #+begin_src bash
  ffmpeg -i anamorphic.mp4 \
    -vf "scale=1280:720,setsar=1" \
    -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p \
    -c:a copy out.mp4
  # setsar=1 stamps SAR 1:1. Without it some players re-stretch.
  #+end_src

** Crop a region

  =crop=W:H:X:Y= — output W×H, top-left corner at (X,Y) measured
  from the source top-left. Omit X:Y to center.

  #+CAPTION: crop a centered 1080x1080 square out of a 1920x1080 source
  #+begin_src bash
  ffmpeg -i input.mp4 \
    -vf "crop=1080:1080" \
    -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p \
    -c:a copy out.mp4
  # default X = (iw-W)/2, Y = (ih-H)/2 → centered.
  #+end_src

  #+CAPTION: remove black letterbox bars (top/bottom 140px each)
  #+begin_src bash
  ffmpeg -i input.mp4 \
    -vf "crop=iw:ih-280:0:140" \
    -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p \
    -c:a copy out.mp4
  # let cropdetect find them automatically (run, read the log, then crop):
  # ffmpeg -i input.mp4 -vf cropdetect -frames:v 200 -f null - 2>&1 | grep -o 'crop=[0-9:]*' | tail -1
  #+end_src

** Crop AFTER scale (order matters)

  Filters run left-to-right. To downscale THEN take a region, list
  =scale= first. The region coordinates are in the SCALED space.

  #+CAPTION: downscale to 720p height, then center-crop a 720x720 square
  #+begin_src bash
  ffmpeg -i input.mp4 \
    -vf "scale=-2:720,crop=720:720" \
    -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p \
    -c:a copy out.mp4
  #+end_src

** Pad / letterbox to a target aspect (16:9 → 9:16 for Reels)

  Scale the video to fit INSIDE the target canvas, then =pad= the
  empty space. =(ow-iw)/2:(oh-ih)/2= centers the scaled video.

  #+CAPTION: 16:9 source → 1080x1920 vertical, letterboxed (black bars)
  #+begin_src bash
  ffmpeg -i landscape.mp4 \
    -vf "scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2:color=black,setsar=1" \
    -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p \
    -c:a copy -movflags +faststart vertical.mp4
  # color=black (default) — set color=white or a hex like 0x1a1a1a as needed.
  #+end_src

  #+CAPTION: blurred-background fill instead of black bars (Reels style)
  #+begin_src bash
  ffmpeg -i landscape.mp4 -filter_complex \
    "[0:v]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,gblur=sigma=20[bg]; \
     [0:v]scale=1080:1920:force_original_aspect_ratio=decrease[fg]; \
     [bg][fg]overlay=(W-w)/2:(H-h)/2,setsar=1[v]" \
    -map "[v]" -map 0:a? \
    -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p \
    -c:a copy -movflags +faststart vertical-blur.mp4
  # bg = blown-up + cropped + blurred copy; fg = letterbox-fit copy on top.
  # -map 0:a? = include audio IF present (the ? makes it optional).
  #+end_src

** Keep vs drop audio

  =-c:a copy= preserves the audio untouched (cheap, no quality loss).
  =-an= drops it entirely (silent output). If you also re-time/scale
  duration, audio needs separate handling — see [[file:video-audio-mux.org][video-audio-mux]].

  #+CAPTION: confirm output dimensions + that the file plays
  #+begin_src bash :role post :path out.mp4
  test -f "$1" || { echo "output missing"; exit 1; }
  ffprobe -v error -select_streams v:0 \
    -show_entries stream=width,height -of csv=p=0 "$1"
  ffprobe -v error -show_entries format=duration -of csv=p=0 "$1"
  #+end_src

* Common pitfalls

  1. *Odd dimension → hard error.* =scale=1080:607= dies with
     "height not divisible by 2". Use =-2= for the auto side, or
     wrap explicit exprs in =trunc(.../2)*2=. Crop is safe with
     even W/H but =crop=iw:ih-281= (odd result) also errors.

  2. *force_original_aspect_ratio can emit an odd dimension.* It
     scales to fit, which may land on an odd number. Chain a second
     =scale=trunc(iw/2)*2:trunc(ih/2)*2= as insurance (shown above).

  3. *Accidental upscale.* =scale=1920:-2= ENLARGES a 1280-wide
     source, softening it and wasting bitrate. Cap with
     =scale='min(1920,iw)':-2= so the cap never enlarges.

  4. *SAR ignored → stretched output.* If the source has non-square
     pixels (SAR≠1:1), scaling without =setsar=1= can leave players
     stretching the result. Read SAR in the pre step; append
     =,setsar=1= after scale when it isn't 1:1.

  5. *Crop X/Y is from the TOP-LEFT, not the center.* A crop that
     runs past the edge (X+W > iw, or Y+H > ih) errors. Omit X:Y to
     center, or clamp against the probed dimensions.

  6. *Crop/pad before scale gives the wrong region.* Filters apply
     in listed order. Decide whether coordinates are in source or
     scaled space and order =scale= / =crop= accordingly.

  7. *Forgetting -pix_fmt yuv420p.* Same trap as [[file:transcode-to-h264.org][transcode-to-h264]] —
     a 4:4:4 or 10-bit source can produce output that won't play in
     Safari/iOS. Always include it for browser/social targets.

* Verification checklist

  - [ ] Output exists + non-zero duration
  - [ ] =ffprobe= width/height match the intended dims (and are even)
  - [ ] No accidental upscale (output ≤ source on the capped edge)
  - [ ] If padded: subject centered, bars symmetric, SAR = 1:1
  - [ ] If cropped: intended region present, no off-by-edge clipping
  - [ ] Browser target: plays in Safari (yuv420p)
