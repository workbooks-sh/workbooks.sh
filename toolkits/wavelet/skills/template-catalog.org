* When to use this
  :PROPERTIES:
  :NETWORK: no
  :DESTRUCTIVE: no
  :REQUIRES: node>=20 wavelet
  :END:

  About to scaffold a new composition with =wavelet init= and
  need to know which =--template= name to use. Or you're
  inheriting a project and want to know what shape its
  scaffolded files imply.

  Not for: authoring NEW templates (that's a separate
  contributor flow — see =wavelet/cli/templates/= in the
  source tree and follow the existing layout).

* Current state — only "default" ships

  As of this writing wavelet ships exactly one template:
  =default=. It's the working reference for the whole format.

  #+CAPTION: list templates ground-truth (lives in the source tree)
  #+begin_src bash :role pre
  ls $(dirname $(command -v wavelet))/../templates 2>/dev/null \
    || echo "(templates live alongside the wavelet binary's install)"
  #+end_src

  #+CAPTION: the source-of-truth listing in this repo
  #+begin_src bash
  ls /Users/shinyobjectz/Apps/workbooks/projects/wavelet/cli/templates
  # → default
  #+end_src

  =--template <name>= is accepted as a flag for forward
  compatibility but today =default= is the only valid value.
  Earlier docs that reference =text-card=, =product-reel=, or
  other speculative names are stale — those templates do not
  exist yet.

* The default template — what you get

  After =wavelet init my-comp=, =my-comp/= contains:

  #+begin_example
  my-comp/
  ├── gamut.html      # the composition source — <gm-doc> root
  ├── styles.css      # CSS for the scenes' overlay HTML
  └── assets/         # placeholders generated by init
      ├── demo.mp4       # 6s test-pattern video (renders out of the box)
      └── vo-tone.mp3    # sine tone (audio cue placeholder)
  #+end_example

  =gamut.html='s shape (verified by reading the template):

  - =<gm-doc fps="30" resolution="1920x1080" aspect="16:9">=
  - Two =<gm-asset>= entries (video + audio)
  - One =<gm-timeline id="main" duration="6s">= with four tracks:
    - =z=0=  =base= — plays the demo video
    - =z=10= =content= — two overlay scenes (=hello= + =payoff=)
    - =z=20= =grading= — CSS-filter color grade for the whole timeline
    - =z=30= =audio= — one audio cue from the VO tone

  The =hello= and =payoff= scenes are full working examples of
  the registered-timeline pattern (see =text-cards.org=).

* Workflow

  #+CAPTION: 1. scaffold from default
  #+begin_src bash
  wavelet init my-comp
  # equivalent: wavelet init my-comp --template default
  cd my-comp
  #+end_src

  #+CAPTION: 2. confirm the scaffold is renderable end-to-end
  #+begin_src bash :role post
  wavelet lint
  wavelet render --out /tmp/scaffold.mp4
  test -s /tmp/scaffold.mp4 \
    && echo "✓ scaffold renders" \
    || { echo "✗ render produced no output"; exit 1; }
  #+end_src

  #+CAPTION: 3. preview live to iterate
  #+begin_src bash
  wavelet preview
  # opens a dev server; edits to gamut.html / styles.css hot-reload
  #+end_src

* Picking a starting shape (since there's only one template)

  Use =default= unconditionally, then strip + rebuild to fit
  your need. The four-track shape (=base= / =content= /
  =grading= / =audio=) is the conventional structure even
  when you're not using one of them:

  | Building                | What to keep / drop                                              |
  |-------------------------+------------------------------------------------------------------|
  | Title-only card         | Drop =base= track + asset; keep =content= with one =<gm-scene>=  |
  | Product reel            | Replace =demo.mp4= with your clip on =base=; rewrite scenes      |
  | Voiceover-led explainer | Replace =vo-tone.mp3= with VO; add a transcript-driven scene list |
  | Lower-third pack        | Drop =base=; multiple short scenes on =content=, no audio        |
  | Music-driven loop       | Drop =vo-tone=; put real music on =audio=; sync scenes to beats  |

  See =text-cards.org= for overlay patterns, =transitions.org=
  for hand-offs, =audio-sync.org= for syncing.

* Common pitfalls

  1. *Asked for a template that doesn't exist.* =wavelet init
     my-comp --template product-reel= may either error or
     silently fall back. Verify: =ls my-comp/= against the
     expected layout above.

  2. *Edited the demo asset paths but kept the placeholders
     in the repo.* =assets/demo.mp4= is a test pattern — if you
     ship without replacing it the rendered video shows
     colored bars. Either swap the file with the same name or
     update =<gm-asset src="...">= to your real asset.

  3. *Deleted the =grading= track entirely.* That's fine, but
     keep track =z= values unique. Two tracks at the same =z=
     have undefined ordering.

  4. *Changed =fps= or =resolution= on =<gm-doc>= but didn't
     re-lint.* =wavelet lint= flags downstream issues (audio
     cue durations that no longer line up with frame boundaries,
     scenes whose tween anchors now fall mid-frame). Run lint
     after any =<gm-doc>= attribute change.

  5. *Expected a wizard.* =wavelet init= is a non-interactive
     scaffold. There's no prompt-driven flow today; for
     interactive workbook authoring see =wb init= instead.

* Verification checklist

  - [ ] Confirmed only =default= exists before assuming any other name
  - [ ] Scaffold renders end-to-end on first =wavelet render=
  - [ ] Placeholder assets replaced (or intentionally kept)
  - [ ] Track =z= values still unique after edits
  - [ ] =wavelet lint= clean
