* wavelet — HTML-composition video renderer                       :toolkit:
  :PROPERTIES:
  :ID:        wavelet
  :VERSION:   0.2.0
  :CLI_BIN:   wavelet
  :STATUS:    experimental
  :SKILL_DIR: skills/
  :END:

  Wavelet renders a *plain HTML + CSS composition* to an mp4 with NO
  external tooling — no Node, no native CLI, no GPU. The pipeline is
  wholly in-nexus:

  1. RENDER (in-sandbox). The carved render core (Blitz HTML/CSS +
     Stylo CSS-animation timeline + a CPU Vello rasterizer), compiled
     to wasm, paints the composition to a deterministic PNG frame
     sequence. It runs in the SAME sandbox as every other command.
  2. ENCODE (host broker). The host muxes that frame sequence into an
     h264/yuv420p mp4 (ffmpeg cannot run in the guest — it is the one
     trusted host-service escape, gated by the =encode= capability).

  The agent AUTHORS an HTML file and runs ONE command:

  #+begin_src bash
  wavelet render clip.html -o out.mp4 --w 1280 --h 720 --fps 30 --duration 4
  #+end_src

  There is exactly one verb today: =render=. Flags: =-o/--out= (mp4
  path, required), =--w=, =--h=, =--fps=, =--duration= (seconds),
  =--crf= (libx264 quality), =--audio= (mp3 to mux as AAC). The
  composition is animated with CSS =@keyframes=; each frame seeks the
  animation clock to =t = frame / fps=, so renders are deterministic.

  This REPLACES the old external =@work.books/wavelet-cli= assumption.
  There is no =init=, =preview=, =inspect= or trimming verb — author
  the HTML directly, render it, done.
