#+TITLE: Toolkit eval suites — ship a toolkit with its own evaluations
#+DATE: 2026-06-09
#+RELATED: AUTHORING.org (the skill/manifest standard), ../runtime/docs/TOOLKITS-V3.org

* Why
  A toolkit already ships *skills* (how to use it) and, for command/posix kinds,
  a *CLI*. An **eval suite** is the third leg: the author's own evaluations,
  bundled IN the toolkit, so

  - the AUTHOR proves the toolkit does what the skills claim, and
  - a CONSUMER can run those evals against their own runtime/data to validate it
    before trusting it (or extend them).

  It is the behavioral complement to =wb toolkit verify=: *verify* asks "does it
  load / is the contract satisfiable" (structural + =:role pre=); *eval* asks
  "does it DO the right thing." Both run under the same default-deny sandbox.

* Location & shape
  One case per file under =toolkits/<name>/evals/*.org=. A case is an
  =:eval:=-tagged node + an org header declaring the expectation. Two tiers; an
  author ships whichever fits (a toolkit may ship both).

** Tier 1 — deterministic (BUILT: =wb toolkit eval <id>=)
   A =:role eval= bash block + a =#+EXPECT:= substring. The block runs under
   =Workbooks.Sandbox= (network-denied, fs-confined, wall-clock-capped) — the
   SAME executor as verify's =:role pre= — and ONLY when =WB_TOOLKIT_EXEC=1=.
   PASS = exit 0 AND stdout contains =#+EXPECT:= (when set).

   #+begin_src org
   ,#+TITLE: git toolkit — version sanity
   ,#+EXPECT: git version

   ,* git is on PATH and reports a version                            :eval:
     ,#+begin_src bash :role eval
     git --version
     ,#+end_src
   #+end_src

** Tier 2 — agent + judge (NEXT, telemetry-scored)
   For "does an AGENT use this toolkit correctly." A =#+TASK:= (what the agent is
   asked to do) + a =#+RUBRIC:= (judge criteria). The harness starts a run
   (=POST /api/run=) with the toolkit in scope, then scores the result + the
   universal =_steps.jsonl= telemetry (=Workbooks.Workflow.Telemetry=) against the
   rubric via a judge model (default =xiaomi/mimo-v2.5=). This is the
   "evaluate against the original author's evaluations" path.

   #+begin_src org
   ,* the agent harvests a brand's palette                            :eval:
     :PROPERTIES:
     :TASK:    Use the brandnana toolkit to harvest tecovas.com's brand palette.
     :RUBRIC:  Output names ≥3 hex colors AND calls the harvest verb (not a guess).
     :END:
   #+end_src

* Running
  - =wb toolkit eval <id>=      — run a toolkit's eval suite (Tier 1 today).
  - =wb dev eval [toolkit]=     — dev-service entry: list eval suites / run them.
  - Gating: Tier-1 bash runs only with =WB_TOOLKIT_EXEC=1= (else reported SKIPPED,
    like verify). Tier-2 needs a runtime + an LLM key.

* Authoring checklist
  - [ ] =evals/= holds one =:eval:= case per file; Tier-1 cases carry =#+EXPECT:=
        + exactly one =:role eval= block.
  - [ ] Deterministic cases are hermetic (no network; the sandbox denies it).
  - [ ] Tier-2 cases carry =:TASK:= + =:RUBRIC:= and name the toolkit verbs the
        agent should reach for.
  - [ ] =wb toolkit eval <id>= passes locally (with =WB_TOOLKIT_EXEC=1=).
