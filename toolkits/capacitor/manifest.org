* capacitor — native iOS wrapper for workbooks                   :toolkit:
  :PROPERTIES:
  :ID:        capacitor
  :VERSION:        0.1.0
  :CLI_BIN:   cap
  :STATUS:    experimental
  :SKILL_DIR: skills/
  :END:

  Wrapper around Capacitor (invoked as ~npx cap~ — no global install needed).
  The Workbooks use case: take a built workbook (=dist/<slug>.html=) and wrap
  it as a native iOS app, then run it in the Simulator, build a signed =.ipa=,
  upload it to TestFlight, and manage the App Store Connect side. It drives
  this through the recipes in =deploy-kit/mobile/=.

  Command surface (~wb forge mobile <cmd>~ — see ~wb forge mobile --help~):
  - =doctor=     — check the iOS toolchain (Xcode.app, Node/Capacitor CLI,
                   CocoaPods) and signing readiness (identity + ASC API key).
  - =dev=        — open the app in the iOS Simulator or a tethered device.
  - =build=      — archive + export a signed =.ipa=. =--export-method
                   development= (default; sideloadable) or =app-store=
                   (distribution, for upload/testflight).
  - =upload=     — upload a distribution =.ipa= to TestFlight via the NATIVE
                   App Store Connect Build Upload API — just the =.p8=, no
                   Fastlane/Transporter. Runs preflight first.
  - =testflight= — Fastlane path: build + upload + release (interactive Mac /
                   macOS CI). Alternative to =build= + =upload=.
  - =create-app= — create the ASC app record for a bundle id (the one step the
                   API key can't do). =--driver playwright= (default) =|
                   produce | manual=.
  - =feedback=   — pull TestFlight tester crash + screenshot feedback (ASC
                   API, read-only).
  - =webhooks=   — list/create/delete ASC webhooks (needs a public sink URL).
  - =release-init= — generate an optional GitHub Actions workflow that ships
                   to TestFlight on an =ios-v*= tag.

  Knobs (env):
  - =WB_FORGE_PUSH=1= — add the =aps-environment= entitlement +
    =UIBackgroundModes= and register for push (token logged). Delivery still
    needs a separate APNs auth key + a sender.
  - =WB_FORGE_NO_MOBILE_NORMALIZE=1= — opt out of the automatic QoL pass
    (=deploy-kit/mobile/lib.sh wb_mobile_normalize=): no-pinch/notch-safe
    viewport, touch-control tuning, smart safe-area, status-bar style, and
    splash compositing. On by default.

  The decision is locked on *Capacitor* (not Tauri-mobile). Each recipe
  scaffolds a real Capacitor 8.x project from =deploy-kit/mobile/template/=,
  copies the workbook HTML into its =www/= web dir, and syncs the native iOS
  project so Xcode can archive it.

  Signing + upload use the *user's own* Apple Developer account and an App Store
  Connect API key (a =.p8= under =~/.appstoreconnect/private_keys/=) — Workbooks
  never holds Apple credentials. Some setup is genuinely one-time and manual
  (Apple Developer Program enrollment, agreements, the App Store Connect app
  record); the ship-a-workbook-to-ios skill walks the user through all of it.

  Requires full *Xcode.app* (CommandLineTools cannot archive or sign), Node 18+,
  and CocoaPods. ~wb forge mobile doctor~ reports readiness per capability
  (dev / build / testflight). ~npx cap --help~ is authoritative for per-command
  detail.
