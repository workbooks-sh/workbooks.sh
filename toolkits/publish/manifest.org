  The publish/identity stack, lifted out of the `work` core
  (M5-publish-to-toolkit — provider/integration logic lives in
  toolkits). The toolkit OWNS the `wb-publish` binary: its source
  is this directory's =bin/= crate, and `work identity …` /
  `work atproto …` exec it when it's on PATH.

  Build / install:

    cargo install --path toolkits/publish/bin

  Two verb groups, same surface they had inside `work`:

  - =wb-publish identity= — the Workbooks Network identity.
    Export/import the did:key + Ed25519 keypair across machines,
    bind a Bluesky account (app-password or the OAuth 2.0
    PKCE + PAR + DPoP flow, `--standalone` needs no engine),
    mint/inspect the X.509 cert for C2PA signing, generate a CSR.

  - =wb-publish atproto= — AT Protocol operations against any PDS,
    signed with the bound session. Publish/delete
    =sh.workbooks.workbook= records, advertise substrate endpoints,
    read follow graphs, stream the firehose, and run the verified
    (C2PA-checked) feed.

  Engine contract: the engine-bind verbs (`bluesky-login`, oauth
  login without `--standalone`, `bluesky-logout`) POST to the
  Workhorse daemon discovered via =~/Workbooks/Engine/listen.json=
  (or WB_DAEMON_URL / WB_ENGINE_URL env). Everything else reads and
  writes the on-disk identity sidecar at
  =<data_root>/Engine/network/identity/= directly — no engine.

  =wb-publish --help= and =wb-publish <group> <verb> --help= are
  authoritative for flags. Skills are end-to-end recipes.
