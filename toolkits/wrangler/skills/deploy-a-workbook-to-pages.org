#+TITLE: Deploy a workbook to Cloudflare Pages
#+CAPTION: Ship a built workbook .html to Pages on the user's own account.

* When to use

The user wants their workbook live on the web at a real URL, hosted on *their
own* Cloudflare account (not our broker / Live URL). One static file, no
server. Preferred over ~wb publish~ when they want to own the hosting + the
bill and keep the artifact entirely on their infrastructure.

* Workflow

The fast path is ONE command — you (the agent) run it via bash; if the user
isn't signed into Cloudflare yet, it opens the browser sign-in automatically,
then stages + deploys. The user never types a command; they just authenticate
in the browser that pops up.

#+begin_src bash
# build the workbook if you haven't (emits dist/<slug>.html)
wb build

# deploy — auto-opens 'wrangler login' if needed, then ships it.
# Project name defaults to the file stem.
wb forge web deploy dist/<slug>.html --to cloudflare
#+end_src

To check / force auth as a separate step (optional):

#+begin_src bash
wb forge web doctor --to cloudflare --login
#+end_src

On success wrangler prints the live ~https://<project>.pages.dev~ URL (and a
per-deployment preview URL).

Equivalent raw wrangler, if you need to do it by hand:

#+begin_src bash :role example
wrangler login                       # browser OAuth into the user's account
mkdir -p /tmp/site && cp dist/<slug>.html /tmp/site/index.html
wrangler pages deploy /tmp/site --project-name <slug> --branch main --commit-dirty=true
#+end_src

* Auth — we set up THEIR CLI, we never hold the token

=wrangler login= opens a browser and signs into the *user's* Cloudflare
account. The OAuth token is stored by wrangler in =~/.wrangler= — Workbooks
never reads, stores, or proxies it. There is no Workbooks OAuth in this path.
Check status any time with =wrangler whoami=.

* Common pitfalls

- *Project name rules*: Cloudflare Pages project names are =[a-z0-9-]= only.
  ~wb forge web deploy~ lowercases + replaces other chars with '-'. Pass
  ~--project-name~ to override.
- *Single file vs dir*: a lone =.html= is staged as =index.html= so it serves
  at =/=. If you deploy a directory, make sure it contains an =index.html=.
- *Dirty git tree*: wrangler refuses a deploy from a dirty tree unless
  =--commit-dirty=true= (the recipe always passes it).
- *First deploy is slower*: the project is auto-created on first
  ~pages deploy~; subsequent deploys are incremental + fast.

* Verification checklist

- =wrangler whoami= shows the expected account/email.
- The printed =*.pages.dev= URL returns 200 and renders the workbook.
- For a workbook that needs the WASM runtime, confirm it boots in the hosted
  page (Pages serves the inlined bundle as-is — no extra build step needed).
