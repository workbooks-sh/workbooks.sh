When the user asks for a *presentation*, *deck*, or *slides*, reach for this — do NOT hand-roll a scroll page. A presentation is reveal.js: a real navigable deck (arrow keys, =f= fullscreen, =o= overview, per-slide URLs via the hash), not a long document. The brand is incidental. The agent calls the *capability* ("make a presentation"); this toolkit resolves it to the reveal.js impl. Swap the impl here without touching any agent that asks for "presentation". Two ways in, by where the content lives: - *From a brandnana deck spec* (slides authored as JSON) — =brandnana book assemble <spec> --out deck.html= already emits reveal.js (the 1280×720 slide design wrapped in =.reveal>.slides>section.slide=, scaled to the viewport). Then =brandnana book publish= it. See =skills/deck.org=. - *From an Org workbook* — render the workbook's =:slide:= / =:section:= nodes as reveal sections. The workbook renderer (org→HTML) takes a presentation mode that wraps each top-level heading as a =<section>= under =.reveal>.slides=. See =skills/org-to-reveal.org=. Either path: hard cuts (=transition:none=), no fade/wipe; the deck stays a single self-contained =.html= (reveal from CDN, content inline).
