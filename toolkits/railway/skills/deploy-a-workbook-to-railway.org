#+TITLE: Deploy a workbook to Railway
#+CAPTION: Ship a built workbook .html as a static site on the user's own Railway account, with the real railway CLI.

* When to use

The user wants their workbook live on the web hosted on *their own* Railway
account (vs Cloudflare Pages, or our broker / Live URL). Railway is a good
pick when they already use Railway for other services, or want the workbook
to live alongside a backend they run there.

* Workflow

Use the real =railway= CLI directly (you, the agent, run it via bash). There is
no =wb forge web= command — that wrapper (and its =deploy-kit/web/railway.sh=
recipe) was removed with the Rust =wb= (2026-06-09). Railway routes to =$PORT=,
so a static file needs a tiny server in front of it; the standard pattern is a
small Caddy image.

#+begin_src bash
# build the workbook if needed (emits dist/<slug>.html)
wb build

# one-time per machine: browser OAuth into the USER'S Railway account
railway login                       # check with: railway whoami

# link a project (or `railway link` an existing one)
railway init --name <slug>

# stage the artifact + a Caddy image that binds Railway's $PORT
mkdir -p site && cp dist/<slug>.html site/index.html
cat > Caddyfile <<'EOF'
:{$PORT:80}
root * /site
file_server
EOF
cat > Dockerfile <<'EOF'
FROM caddy:2-alpine
COPY Caddyfile /etc/caddy/Caddyfile
COPY site /site
EOF

# build the Dockerfile + deploy; then mint a public URL if there's none yet
railway up
railway domain
#+end_src

* Auth — we set up THEIR CLI, we never hold the token

=railway login= opens a browser and signs into the *user's* Railway account.
The token is stored by railway in =~/.railway= — Workbooks never reads, stores,
or proxies it. Check with =railway whoami=.

* Common pitfalls

- *$PORT*: Railway injects =$PORT= and routes to it. The Caddyfile above binds
  =:{$PORT:80}=; a static server that hardcodes :80 fails Railway's health check.
- *Project linking*: =railway up= needs a linked project — =railway init --name
  <slug>= when the cwd isn't linked yet, or =railway link= to target an existing
  project.
- *Build vs static*: deploying the Caddy Dockerfile (rather than leaning on
  Railway's buildpack auto-detection) makes a bare HTML file deploy predictably.

* Verification checklist

- =railway whoami= shows the expected account.
- =railway status= shows the project + a successful deployment.
- The =railway domain= URL returns 200 and renders the workbook.
