  A *knowledge + assets* toolkit: a small org-mode CMS you can drop into any
  website. Three parts ship together —

  - =dist/orgitorial.js= — the renderer. One self-contained file, *zero
    dependencies*. Pure string→string (=render(orgText, opts) -> html=), so it
    runs in a browser =<script>= (as =window.Orgitorial=), as an ES module,
    in Node at build time, and in the runtime's QuickJS wasm lane. No DOM, no
    Node APIs. Malformed org never throws — it degrades to paragraphs, and
    unsupported constructs are preserved as escaped =.org-raw=, never dropped.
  - =dist/orgitorial.css= — the skin. A complete editorial stylesheet for
    every class the renderer emits, themed *entirely* through =--org-*= custom
    properties, with a light default and a =[data-org-theme=dark]= variant.
  - =skills/= — how to use it: plug-in recipes, the authoring subset, the
    component/class catalog, and the theming variable system.

  The contract between the two halves is the *CSS class API* — the renderer
  emits a fixed set of classes (=article.org-doc=, =h2.org-h=, =pre.org-src=,
  =li.org-check=, =details.org-drawer=, …) and the CSS styles exactly those.
  Document & honor that contract; it is what makes the toolkit
  framework-agnostic. Render the HTML *string* and you can consume it from
  Svelte, React, or plain HTML alike — there are no web components and no
  framework dependency anywhere.

  The supported org subset is the blogging 90%: metadata
  (=#+TITLE/#+AUTHOR/#+DATE/#+keywords=), headlines 1–4 with TODO keywords and
  =:tags:=, paragraphs, =*bold* /italic/ _underline_ +strike+ =verbatim=
  ~code~=, =[[links][desc]]= and images, plain/ordered/nested lists with
  =[ ]/[X]= checkboxes, tables, =#+begin_src/quote/example/verse= blocks,
  =:PROPERTIES:= drawers, footnotes =[fn:1]=, horizontal rules, and inline
  =<timestamps>=. See =skills/authoring= for the full map.

  An article can also be a *workbook*: three living-block types let a post carry
  interactive content — a =#+begin_src mermaid= diagram, a =#+begin_src html
  :app= (or =#+begin_export html=) mini-app, and a =:width column|wide|full=
  modifier to break any block out of the editorial column (full-bleed, never
  inner-scrolling). The renderer stays zero-dep — it only emits the markup; the
  host page calls the new browser-only =Orgitorial.activate(document)= to run app
  scripts and lazy-render mermaid from a CDN. See =skills/components= (contract)
  and =skills/authoring= (when to reach for one).

  Intended consumers (the toolkit is built to be re-themed, not forked):

  - *Any website* — static site, server-rendered page, or single HTML file:
    link the css, render the string. Three lines minimum (see =integrate=).
  - *The living-lander blog* — Workbooks' own lander renders posts authored in
    =.org=; its brand tokens map onto the =--org-*= vars.
  - *bit.ml stories* — long-form story pages whose palette/type map onto the
    same vars, so a story inherits the editorial rhythm for free.

  Quick proof: open =dist/specimen.html= — a single self-contained page that
  loads the css + js, renders a kitchen-sink post about org-mode itself
  (every supported construct), and has a light/dark toggle. The raw source is
  =examples/kitchen-sink.org=. Tests: =node test/render.test.mjs=.
