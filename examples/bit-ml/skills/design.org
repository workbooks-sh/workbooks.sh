#+TITLE: skill: design — laws for agents writing content (not building the site)

Read this at orientation. DESIGN.md is the authoritative spec for the site;
this skill distills only the laws that govern WHAT YOU WRITE — voice, banners,
blocks, whitespace, badges. Build questions → DESIGN.md. Writing questions → here.

* §6 voice law (verbatim — no paraphrase)

  - Headlines: sentence case, present tense, no clickbait curl
    ("beats the supercomputers it replaced", never "You won't believe…").
  - Deks carry the actual information. A reader who stops at the dek is
    INFORMED, not teased.
  - Numbers always sourced. Reading times honest.
  - Register: a sharp colleague, not a hype account.
  - No pitch-beat padding. No "in the rapidly evolving landscape of".

* banner law

  Stories may carry ONE banner image. Most stories don't earn one.

  Earn criteria: story has genuine visual weight — hardware announcement,
  a chart worth photographing, a scene with real editorial texture. Pure
  earnings-update bites do not earn banners. When in doubt: no banner.

  Rules when you use one:
  - Abstract or editorial image. NEVER text in the image — the head and dek
    are the text.
  - Aspect ratio 16:9.
  - Written to =content/images/<slug>-banner.webp= via the image tool.
  - Budget: 2 images per run across all stories in that run.
  - After writing: add =banner= and =bannerAlt= to the manifest row.
    =bannerAlt= is a plain-language description of what is depicted
    (for screen readers and broken-image fallback).
  - No banner on Bite cards — the stack stays fast. Banner renders on the
    story page (above the org body) and on the WireLead (below the dek).

  Manifest row fields:
  #+begin_src json
  { "banner": "content/images/my-slug-banner.webp",
    "bannerAlt": "Abstract circuit lattice in blue and silver" }
  #+end_src

* interactive block law

  Reach for a block when it EARNS its place — when structure or 30 seconds
  of interaction genuinely beats the paragraph. Default to prose.

  Three signals to reach for a block:
  - Flow, pipeline, or state machine → mermaid diagram (structure beats prose).
  - Reader needs to feel the point, not read it → :app mini-app
    (30 seconds of interaction beats a chart).
  - Figure or pull-quote needs room → :width wide or full (content earns the space).

  Orgitorial syntax (only these forms render live):

  Mermaid:
  #+begin_src org
  ,#+begin_src mermaid
  flowchart LR
    A --> B
  ,#+end_src
  #+end_src

  Mini-app:
  #+begin_src org
  ,#+begin_src html :app :width wide
  <div>…self-contained html + inline script…</div>
  ,#+end_src
  #+end_src

  Width modifier on any block:
  #+begin_src org
  ,#+begin_src mermaid :width wide
  ,#+begin_src html :app :width full
  ,#+begin_quote :width wide
  #+end_src

  Hard rules for mini-apps:
  - CONDENSED: auto-height, never inner-scroll, no max-height, no overflow:scroll.
    A cramped scrolling box is worse than the paragraph it replaced.
  - SELF-CONTAINED: inline styles, inline script. No external build.
    Module scripts may import wasm — keep payload lean.
  - :width wide is the default for interactive. :width full for hero-scale only.
  - After writing: run =wb content check= and do a render sanity read-back.
    A story with a broken block does not advance.

* whitespace & length discipline

  Body column: 68ch max. One idea per story — if the skeleton holds two, write
  one and note the second for desk.

  Cut what does not earn its place. Dek ≤ 2 sentences. Body tight.
  Block whitespace: one blank line before/after a block in org is enough —
  the page CSS handles visual spacing.

* section badge system (fixed four sections)

  Sections: AI · MARKETS · CHIPS · POLICY. These four only.

  Badge is the ONLY color carrier on a story page besides wire blue
  (interactivity) and up/down in market data.

  Set =section= in the manifest row to one of the four lowercase keys:
  | section | accent  |
  |---------+---------|
  | ai      | #0a52e0 |
  | markets | #0a7d4f |
  | chips   | #b8860b |
  | policy  | #7a4988 |

  One section per story. The renderer handles badge styling from =sections.js=.

* what stays out

  No tinted card backgrounds. No colored section bands. No gradients. No dark
  surfaces. No text inside images. No newsletter prompts. No decorative icons.
  Page is monochrome except badges + wire blue + market up/down.
