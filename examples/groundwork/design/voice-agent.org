* The referent

  A persistent VOICE agent the founder talks to at length — walking, driving,
  thinking — that holds the entire repo in its head at the management
  altitude, not the code altitude. It is the live, continuous version of
  groundwork's batch pipeline: instead of recording a memo and transcribing
  it later, every conversation IS a groundwork source, ingested
  automatically.

  It is a CHIEF OF STAFF, not a coder:
  - discusses the actual state of the repo — what's done, what's not, what
    drifted — grounded in real queries, never vibes
  - absorbs rambling (filler, half-ideas, concept-explorations) and still
    maintains a concrete roadmap underneath
  - files issues, sets up audits, dispatches deep-research agents to
    investigate theories, manages the board
  - SETS THE STAGE for the coding agent (Claude Code): when a coding session
    opens, the highlighted state is sitting there waiting in the repo
  - conversational laws: it does NOT interview, survey, or interrogate. It
    thinks alongside, pushes back, continues the thread, keeps talking and
    reasoning until told "stop". Ongoing conversation, not Q&A.

  Anchor: ElevenLabs Agents (Conversational AI) — already paid for, already
  handles the hard real-time parts. Collision to avoid: this is NOT another
  tenant product agent (Waldo, bit.ml crew) and NOT the autopoet (which
  grows capabilities). It is the founder's management peer over the repo.

* Why ElevenLabs Agents over Gemini Live

  - Already paying for it; STT (scribe) already proven in this repo.
  - The platform owns the brutal parts: turn-taking, interruption, long
    calls, voice quality, mobile clients (hosted call link + Swift /
    React-Native / JS SDKs) — we write ZERO realtime code.
  - Server tools: the agent calls our webhooks with JSON-schema'd args —
    that is the entire integration surface we must build.
  - Post-call webhook delivers the full transcript when the call ends —
    every conversation auto-becomes a =sources/= entry. Groundwork ingestion
    for free.
  - Bring-your-own-LLM is supported if the bundled brains are too small for
    repo-level reasoning.
  - Gemini Live remains the fallback if 11labs latency/reasoning disappoints;
    the bridge (below) is provider-agnostic on purpose.

* Architecture — the agent is thin; the bridge is the product

  #+begin_example
  phone (11labs app / call link / later: workbook mobile app)
        │  voice
        ▼
  ElevenLabs Agent  (persona prompt + server tools)
        │  HTTPS webhooks (HMAC)
        ▼
  THE BRIDGE — small authed HTTP surface on the runtime (:4000 web plane)
        │
        ├─ repo_state(query)      → bd ready/show/list + git log + examples
        │                           README — answers "where are we?"
        ├─ capture(text, kind)    → append to groundwork sources/captures/
        │                           (idea | decision | question | rant)
        ├─ file_issue(attrs)      → bd create (founder lane) — reuses the
        │                           Autopoet.file_issue seam pattern
        ├─ dispatch_research(q)   → files a research-lane issue a deep-
        │                           research agent picks up async; results
        │                           land back on the board
        ├─ board(read|move|add)   → the org Kanban (below)
        └─ post-call webhook      → full transcript → sources/<date>-call/
  #+end_example

  The voice agent holds NO state. All state lives in the repo + bd. Any
  provider that can call webhooks can drive the same bridge.

* The single source of truth — and the bd wrinkle

  Constraint: =.beads/= is local-only and git-ignored, FOREVER (public-repo
  liability; settled 2026-06-09). So bd is the working ledger but cannot be
  the git-visible truth that Claude Code validates across sessions.

  Resolution — two layers, one direction of flow:
  - *bd* = the operational ledger (issues, lanes, statuses). The bridge
    writes here live during calls.
  - *=examples/groundwork/BOARD.org=* = the committed, git-visible board:
    a generated org Kanban (epics → tasks with states, datestamps, links to
    bd ids) the bridge regenerates and commits after every call. THIS is the
    single source of truth in the repo. Claude Code reads it at session
    start; the founder can open it like a document; history is the git log.

  BOARD.org is generated FROM bd, never hand-edited — no two-way sync, no
  drift war. (Org's parsability is what makes the generation testable —
  the "can't write a test suite for Markdown" thesis, applied to ourselves.)

* Persona laws (the def, when written)

  - Never survey-mode. No "on a scale of", no question batteries. One
    thought, continued, until the founder redirects or says stop.
  - Grounded or silent: any claim about repo state must come from a
    repo_state call made in THIS conversation, not memory.
  - Capture relentlessly, interrupt never: rambling gets distilled into
    captures/issues in the background of the conversation, not read back.
  - Maintain the roadmap as the spine: every conversation ends (post-call)
    with the board reconciled — new items filed, stale items flagged.
  - It does not code, and it does not promise code. It stages work for the
    coding agent and says exactly that.
  - Pitch rule applies: never "sites that run themselves".
